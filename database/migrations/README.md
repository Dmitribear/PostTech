# Порядок миграций сборочной ветки

Используйте только явный порядок из [`../migration-plan.json`](../migration-plan.json)
для новой пустой локальной базы. Применение только `*.sql` из этой папки пропустит
миграции `main/`; рекурсивная сортировка тоже не задаёт правильного порядка.

Исходные SQL обеих веток сохранены, а `0011_team_workflow.sql` согласует
транзакционные заявки, директора, окончательное HR согласование и баланс.
Подробный контракт: [`docs/team-backend-contract.md`](../../docs/team-backend-contract.md).

Это **не план автоматического обновления общей Supabase**. Для существующей базы
сначала нужно сверить применённые миграции и данные, особенно исторические
одобрения, резервы и остатки. Текущая работа общую базу не меняет.
