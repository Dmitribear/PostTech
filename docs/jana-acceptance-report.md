Что изменилось:

- Фильтр создания заявки больше не считает «отправленной», «созданной» и
  «оформленной» просьбой подать новую заявку. Такие вопросы проходят обычный

- В поисковых примерах карточки `request_status` уточнено значение `pending`,
  добавлены формулировки о `rejected`, результате рассмотрения и комментарии.
  Точные вопросы оценочных наборов в поисковые примеры не добавлялись.
- При проверке реального API обнаружена устаревшая цитата: опубликованная
  статья уже описывала `cancelled` и комментарий руководителя или HR. После
  просмотра всего источника локальная демо-статья, цитата и её SHA-256
  синхронизированы с опубликованным текстом. Общий Supabase не изменялся.
  Локальный `seed_jana_demo.sql` пересобран из JSON; в базу он не применялся.
- HTTP-скрипт теперь проверяет соответствие всех 15 карточек опубликованным
  источникам ещё до вопросов. Отказы не могут скрыть устаревшую карточку;
  проблемы записываются в `catalog_source_issues` и делают прогон неуспешным.

## Исходный замер — до исправления

Далее сохранены исходные результаты, причины отказов и полный список вопросов.
Файлы `jana-acceptance-v1-local.json` и `jana-acceptance-v1-http.json` не перезаписывались.

17 октября 2026 года проверены 50 новых вопросов на локальной модели и затем
те же 50 вопросов через Vite → FastAPI → общий Supabase под тестовым сотрудником.
Результаты совпали: **40/50**, включая **20/30 правильных ответов по базе**
и **20/20 правильных отказов или уточнений**. Десять ошибок — лишние отказы
на вопросы, для которых ответ в FAQ есть. Неправильных ответов с цитатами
или выдуманных кадровых правил на этом наборе не обнаружено.

### Что проверялось

- 30 вопросов охватывают все 15 FAQ-карточек: переформулировки и пять вопросов
  с опечатками. Остальные 20 проверяют неизвестные правила, дополнительные
  условия, посторонние темы, персональные данные, команды на действия,
  подмену инструкций, неоднозначность и составной вопрос.
- Ожидания зафиксированы до первого прогона. Тексты вопросов отсутствуют среди
  поисковых примеров FAQ и предыдущих оценочных наборов. Точное отсутствие
  повторов проверяется тестом; смысловые пересечения тем намеренны.
- При подготовке исходного замера FAQ, пороги и код ответов агента не изменялись.
  Первый прогон дал 40/50; усиленная проверка источников подтвердила результат.
- Проверяется ожидаемая карточка, точная цитата, активность источника, SHA-256
  всего текста, заголовок, адрес защищённого источника и отсутствие добавленного
  моделью текста. Отказ должен быть без источников и `grounded=false`.
- HTTP-прогон действительно вошёл через Supabase Auth, прочитал 11 опубликованных
  статей и проверил, что вопрос и чтение источника без токена возвращают 401.
  Он не создавал заявки, не менял статьи и не назначал курсы.

Это ручной acceptance-набор для учебной базы, а не статистически независимый
промышленный benchmark. Он не гарантирует отсутствие ошибок на других вопросах.
После анализа ошибок набор становится регрессионным: для оценки следующих
улучшений нужен ещё один заранее отложенный набор. HTTP-прогон проверяет API
через прокси фронтенда, а не клики в браузере или все три роли.

Дополнительно прошли 73 unit/contract-проверки Jana и скриптов оценки,
включая проверку неверных источников, неполных ожиданий, повреждённой модели
и запрета отправки тестовых доступов на внешний адрес. Это отдельные проверки
кода; они не увеличивают результат 40/50 по новым вопросам.

- HTTP через Vite и Supabase: медиана 832.7 мс, p95 854.9 мс.

Первичная загрузка модели и индекса в локальном прогоне: 4.069 с. Это один последовательный замер на компьютере разработчика; HTTP-модель
уже была прогрета. Время запросов включает быстрые отказы до поиска. Это не
нагрузочный тест и не обещание такой скорости на другом компьютере.

## Повторить основной прогон

После установки зависимостей и модели из корня проекта, используя Python
своего виртуального окружения:

```powershell
python -m scripts.evaluate_jana_local --cases knowledge_base/demo/acceptance_v1.json --output .venv/jana-acceptance-local.json
```

Для HTTP запустите API на 8000 и фронтенд на 5173. Создайте игнорируемый файл
`.venv/jana-test-login.json` с полями `email` и `password` тестового сотрудника,
после чего выполните:

```powershell
python -m scripts.evaluate_jana_http --credentials-file .venv/jana-test-login.json --output .venv/jana-acceptance-http.json
```

В окружении автора команды запускаются через `.\.venv\runtime\Scripts\python.exe`;
в новом окружении из инструкции команды — через `.\.venv\Scripts\python.exe`.
HTTP-скрипт также понимает существующий приватный файл с `accounts.worker`.
Его можно передать напрямую через `--credentials-file`. Пароли и токены
не включаются в отчёт; URL назначения ограничен loopback API.

Код выхода **1** при текущем наборе означает обнаруженные несовпадения,
а не неудачный запуск модели. Код **0** — все оценённые случаи прошли;
код **2** — ошибка подготовки или прерванный HTTP-прогон. Платный OpenAI
не вызывается ни одним из этих скриптов.
