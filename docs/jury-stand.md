# PostTech: показ с компьютера

## Запуск за минуту

1. Подключите компьютер к интернету: приложение работает локально, Auth и данные находятся в Supabase.
2. Откройте `Start PostTech Docker.cmd` в корне проекта. Рабочий адрес: **http://127.0.0.1:8000**. Затем выполните `.venv/Scripts/python.exe scripts/check_release.py`.
3. Для настоящего входа используйте один из трёх аккаунтов из приватного файла `.local/jury-access.html`. Кнопка «Демо-вход» включает отдельный режим без сервера.
4. После показа остановите контейнеры через `docker compose stop`.

Повторный запуск использует уже работающий процесс PostTech. Если порт занят другой программой, запуск остановится с объяснением. Для другого порта: `powershell -ExecutionPolicy Bypass -File scripts/start_jury.ps1 -Port 8012`.

## Три роли

| Аккаунт | Что показывать |
| --- | --- |
| Алия, сотрудник | Главная, отпуск, история и уведомления, назначенный курс, Jana |
| Ерлан, руководитель | Заявки команды, согласование, обучение команды, собственная заявка |
| Мадина, HR | Сотрудники, заявки, приглашения и обучение |

Пароли не включены в презентацию и документацию. `.local` исключён из Git. При смене роли нажмите «Выйти» и войдите другим аккаунтом. Вкладки одного браузера разделяют сессию: не показывайте одновременно три роли в обычных вкладках. Для одновременного показа используйте отдельные профили браузера.

Все три аккаунта и их записи вымышленные. При повторении показа выбирайте новые будущие даты, которые не пересекаются с уже созданным отпуском. Не удаляйте историю ради красивого экрана.

## История для демонстрации

1. Алия открывает главную и создаёт отпуск на один будущий день. До отправки виден согласующий.
2. Ерлан входит и согласует заявку с коротким комментарием.
3. Алия видит решение и историю. На стенде уже есть пример согласованной заявки за 26 ноября 2026 года.
4. В обучении открыт назначенный курс «Первый рабочий день в цифровом HR». Прочитайте материал, подтвердите прочтение и ответьте на вопросы.
5. В Jana спросите «Как оформить отпуск?», откройте источник. Затем спросите «Какая зарплата у моего руководителя?» и покажите отказ.
6. Объясните случай отпуска руководителя: заявка идёт вышестоящему руководителю или HR. Самосогласование запрещено. Если подходящего согласующего нет, подача блокируется.

Перед защитой выполните проверку `python scripts/verify_jury_stand.py --base-url http://127.0.0.1:8000 --read-only`. Полная репетиция: `python scripts/verify_jury_stand.py --base-url http://127.0.0.1:8000`. Она изменяет только помеченные тестовые аккаунты, сохраняет ключ отправки в `.local/jury-rehearsal.json` и при повторе использует ту же заявку.

## Если что-то не работает

| Симптом | Действие |
| --- | --- |
| Нет подключения к Supabase | Проверьте интернет. Для защиты откройте локальную презентацию и резервный ролик. |
| Вход не проходит | Проверьте роль и почту в приватной памятке. Не нажимайте регистрацию для тестового аккаунта. |
| Jana долго отвечает | Дождитесь ответа. При недоступности модели возвращается точная цитата из базы с явной пометкой. |
| Нет письма | Тестовый Resend отправляет только на почту владельца. На вымышленные jury-адреса письма не отправляются. |
| Сервер не готов | Прочитайте `.local/jury-8010.stderr.log`. Проверка готовности проверяет настоящий запрос к базе и наличие миграции 0006. |

## Проверенная чистая установка

17 октября 2026 года: создана отдельная копия исходников без `.env`, `.local`, зависимостей и сборки. В новом Python 3.13 окружении установлены версии из `requirements.lock.txt`, затем выполнены `npm ci` и production build. Копия запущена на 8011 с приватной конфигурацией, проверены готовность и вход всех трёх ролей. Повторный запуск и остановка прошли. Временный `.env` после проверки удалён. Docker в этом прогоне не проверялся.

Для воспроизведения из корня исходного проекта:

```powershell
python scripts/prepare_clean_copy.py --destination E:\PostTechClean
cd E:\PostTechClean
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
cd frontend
npm ci
npm run build
cd ..
```

Приватно настройте `.env` по `.env.example`, примените миграции 0001–0016 к своему Supabase; 0014 выполняется отдельно перед 0015. Для нового проекта добавьте демонстрационные данные и подготовьте аккаунты по README. Затем откройте `Start PostTech.cmd`. Не включайте `.env` или `.local` в передаваемый архив.

## Границы прототипа

Подача резервирует доступные дни, согласование подтверждает резерв; официальный кадровый остаток остаётся read-only. После решения есть отдельное оформление HR. Очередь 1С/Documentolog подготовлена, внешние системы не подключены. База знаний и учебные материалы демонстрационные. Публичного размещения нет. Мобильная версия является адаптацией веб-портала.

Новые сценарии 7–10 и ограничения локализации: [проверка этапов](stages-7-10.md).

## Актуальный запуск Docker

Три контейнера: frontend, api, integrations. Запуск: `docker compose up --build -d --remove-orphans --wait`. Портал: http://localhost:8000. Проверка БД: `/api/v1/health/ready`. Локальная модель опциональна, см. [Docker](docker.md). Не смешивайте этот адрес с Python-стендом на 8010.
