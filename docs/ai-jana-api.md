# AI Jana: API для backend и frontend

Ветка `Integration`: локальный Qwen3.5-9B читает полную базу опубликованных статей,
за один проход определяет намерение и выбирает подтверждающие предложения. Сервер
проверяет JSON, ID и целостность источников, затем возвращает точные цитаты и ссылки.
Смысловая правильность оценивается отдельно; подлинность цитат не гарантирует её.
Текущая демо-база содержит 11 вымышленных статей;
FAQ-примеры и тестовые вопросы не используются. Есть экспорт одобренного отпуска в `.ics`.
Поля ответа AI и пути `/ask`, `/sources/{id}` сохранены.
[Запуск и ограничения](ai-jana-agent.md).

## Демо без Supabase

```powershell
python -m pip install -r requirements-dev.txt
python -m scripts.prepare_jana_reader
powershell -File scripts/start_jana_reader.ps1
python -m uvicorn examples.jana_local_demo:app --host 127.0.0.1 --port 8002
```

Страница http://127.0.0.1:8002 использует настоящую локальную модель и вымышленные
данные. Авторизации нет; только localhost. `/demo/leave.ics` скачивает вымышленный
отпуск. Это отдельное приложение, не production-маршрут и не резервный API.
Старый `examples.jana_mock` на 8001 оставлен для фиксированных UI-примеров.

## Авторизация рабочего API

Backend: http://localhost:8000, OpenAPI: `/openapi.json`, Swagger: `/docs`.
Все маршруты ниже требуют `Authorization: Bearer <Supabase access_token>`.
Роль определяется сервером по привязанному HR-профилю. Нельзя передать роль,
employee_id или историю диалога в запрос AI. Общие статьи доступны всем трём ролям;
личные/закрытые документы в таблицу `knowledge_articles` загружать нельзя.

### POST /api/v1/ai/ask

```http
POST /api/v1/ai/ask
Authorization: Bearer <access_token>
Content-Type: application/json

{"question":"Где найти назначенные курсы?"}
```

```json
{
  "answer": "Демонстрационные материалы:\n\nВ демо-прототипе откройте Jana Academy, чтобы увидеть каталог и назначенные вам курсы. [1]",
  "sources": [{
    "id": "20000000-0000-4000-8000-000000000007",
    "title": "Демо: назначения Jana Academy",
    "url": "/api/v1/ai/sources/20000000-0000-4000-8000-000000000007",
    "excerpt": "В демо-прототипе откройте Jana Academy, чтобы увидеть каталог и назначенные вам курсы."
  }],
  "grounded": true,
  "escalation_suggested": false,
  "mode": "excerpts"
}
```

Пример показывает форму ответа; точный выбор цитат модель может изменить.
`question`: 3–2000 символов после trim; лишние поля — 422. Каждый вопрос независим.
Модель получает весь текущий вопрос, без старого ограничения MPNet в 128 токенов.

| Поле | Что показывает UI |
| --- | --- |
| `answer` | Обычный текст; не вставлять как HTML. |
| `sources` | От нуля до нескольких источников, не более одной записи на статью. Отказ выполнить действие или раскрыть личные данные также может сопровождаться цитатой о границах/порядке. |
| `sources[].excerpt` | Дословная подстрока статьи. До восьми выбранных фрагментов, суммарно до 2400 символов цитат вместе с промежуточным контекстом. |
| `sources[].url` | Внутренний путь защищённого API; открывать с Bearer-токеном. |
| `grounded` | Цитата существует в активном источнике; не гарантия релевантности. |
| `escalation_suggested` | Предложено обращение к HR; автоматически ничего не отправляется. Простое уточнение вопроса имеет `false`. |
| `mode` | `excerpts` или `refusal`. `generated` сохранён в типе для совместимости. |

Отказ и просьба уточнить вопрос — обычный HTTP 200:

```json
{"answer":"Не нашёл в опубликованной базе достаточного подтверждения для ответа на этот вопрос. Уточните у HR.","sources":[],"grounded":false,"escalation_suggested":true,"mode":"refusal"}
```

Уточнение не требует эскалации:

```json
{"answer":"Уточните, о чём идёт речь: что именно вы хотите сделать или проверить?","sources":[],"grounded":false,"escalation_suggested":false,"mode":"refusal"}
```

При частичном ответе сервер явно сообщает о непокрытой части и возвращает цитаты
для подтверждённой части. `grounded` означает происхождение цитат, а не полноту
ответа. UI не должен считать `mode=excerpts` признаком выполнения действия.
Доступ к личным данным и изменениям не предоставляется модели независимо от её решения.

Недоступный reader, занятость, сбой базы или превышение полного контекста — 503,
без платного fallback. Неверный JSON/ID выбора даёт безопасный отказ с HTTP 200.
Изменённые статьи читаются заново, их фрагменты получают новые ID; неактивные
исключаются. Новая статья не требует отдельной FAQ-карточки.

### GET /api/v1/ai/sources/{article_id}

Возвращает `{id,title,content,source_title,source_url}` активной статьи.
`source_url` — необязательный внешний документ (в демо null); `sources[].url`
всегда ведёт на внутреннюю карточку. Отсутствующая/неактивная статья — 404.

Кнопка источника должна выполнить fetch с токеном и показать `content` как текст.
Обычная ссылка не добавляет заголовок авторизации. Не помещайте токен в URL.

```ts
export async function readSource(base: string, token: string, sourceId: string) {
  const response = await fetch(`${base}/api/v1/ai/sources/${encodeURIComponent(sourceId)}`, {
    headers: { Authorization: `Bearer ${token}` },
  });
  if (!response.ok) throw new Error(`Источник: HTTP ${response.status}`);
  return response.json();
}
```

### GET /api/v1/requests/{request_id}/calendar.ics

Кнопка «Скачать для Google Calendar» на карточке **одобренного отпуска**.
Сервер повторно читает заявку и проверяет права, тип, статус и даты; скрыть кнопку
на frontend недостаточно. Права: владелец, его непосредственный руководитель, HR.

Ответ: `Content-Type: text/calendar; charset=utf-8`,
`Content-Disposition: attachment; filename="leave-<uuid>.ics"`, `Cache-Control: no-store`.
Даты берутся из заявки; конечный день включён. Файл не содержит персональных комментариев.
UUID параметра обязателен. Для pending/rejected/cancelled, аванса или неверных дат — 409.

Готовая функция `downloadLeaveCalendar` находится в `examples/jana.types.ts`:
fetch с Bearer-токеном → Blob → временная download-ссылка. Токен остаётся в заголовке.
После скачивания покажите инструкцию: Google Calendar на компьютере → Настройки →
Импорт и экспорт → выбрать файл и календарь → Импортировать.
Не пишите «Событие добавлено»: backend только сформировал файл.
Автообновления и отмены нет; повторный импорт может дать дубликаты.
У курсов нет подтверждённых дат, поэтому кнопка экспорта обучения пока не нужна.

## Ошибки и подключение

| HTTP | Действие UI |
| --- | --- |
| 401 | Обновить сессию или предложить вход. |
| 403 | Показать отсутствие доступа/HR-профиля. |
| 404 | Источник или заявка недоступны. |
| 409 | Файл доступен только для одобренного отпуска с корректными датами. |
| 422 | Исправить тело/UUID; `detail` содержит ошибки валидации. |
| 503 | Техническая недоступность, а не отсутствие знаний. |

Backend пока не включает CORS. Для Vite используйте proxy `/api`; демо-страница
8002 работает с того же origin. Не отправляйте Bearer-токен на произвольный URL
из ответа модели. Отменяйте устаревшие запросы чата, не повторяйте ошибки бесконечно.

Для backend: установить requirements, выполнить `scripts.prepare_jana_reader`,
запустить `scripts/start_jana_reader.ps1`, настроить Supabase Auth и ключи.
Общий Supabase уже подготовлен: повторно применять миграции и seed не нужно.
Для новой базы следуйте README; seed не выполняется автоматически.
Для frontend: существующий `/ask`, карточка источника, состояния отказа/уточнения/503
и кнопка скачивания файла. Несколько источников и уточнение без рекомендации HR
должны отображаться корректно.

Проверка локальной модели:
`python -m scripts.evaluate_jana_reader --mode local --cases knowledge_base/demo/independent_agents_v2.json --development --output .venv/jana-reader-dev-01.json`.
Это разработка на известном наборе, без платного API. Слепые прогоны требуют
фиксации кода и набора перед запуском. Старый `evaluate_jana_local` проверяет FAQ,
а не текущий HTTP-агент. Набор проверок и ограничения описаны в
[документации агента](ai-jana-agent.md).

Нативный Windows-запуск — основной. Текущий Docker Compose не поднимает reader;
loopback хоста недоступен как loopback контейнера. Не считайте Compose полным
развёртыванием новой Jana.

Текущий reader: Qwen3.5-9B Q4_K_M, около 6,17 ГБ; параметры манифеста —
8192 токена и 20 слоёв на GPU. На конфигурации 16 ГБ RAM / 4 ГБ VRAM часть
вычислений остаётся на CPU. UI должен сохранять состояние ожидания, пока запрос
выполняется, и отдельно обрабатывать 503. Это не обещание фиксированной задержки.
