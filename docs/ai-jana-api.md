# API локальной Jana

Все production вызовы требуют `Authorization: Bearer <access_token>` и связанного HR-профиля. Доступны worker, manager, director, hr_admin. Ассистент читает только общие опубликованные актуальные статьи; роль не предоставляет ему доступ к персональным сведениям.

## Вопрос

`POST /api/v1/ai/ask`, JSON: `{"question":"Кто окончательно согласует отпуск?"}`. Вопрос3–2000символов. `Accept-Language: kk` показывает примечание об исходном русском языке; цитаты сохраняются дословно.

```json
{
  "answer": "Демонстрационные материалы: ... [1]",
  "sources": [{
    "id": "20000000-0000-4000-8000-000000000001",
    "title": "Демо: оформление заявки на отпуск",
    "url": "/api/v1/ai/sources/20000000-0000-4000-8000-000000000001?version=<snapshot>",
    "excerpt": "Точная цитата из текущего источника.",
    "version": "<snapshot>",
    "freshness": "reviewed",
    "updated_at": "...",
    "reviewed_at": "...",
    "review_due_at": "..."
  }],
  "grounded": true,
  "escalation_suggested": false,
  "mode": "excerpts"
}
```

Пример показывает структуру, многоточия не являются фактическим ответом. `version` — непрозрачный токен снимка. `grounded` подтверждает наличие цитаты, не смысловую правильность. Нормальный отказ: HTTP200, sources=[], grounded=false, mode=refusal. Уточнение может иметь escalation_suggested=false; нельзя определять необходимость HR только по grounded.

Jana не создаёт HR обращения автоматически. Кнопка передачи вопроса использует отдельный `/workspace/tickets` и явное согласие пользователя.

## Источник

`GET /api/v1/ai/sources/{UUID}?version=<snapshot>` с тем же Bearer. Возвращает id, title, content, source_title, source_url и метаданные версии/проверки. Открывайте внутренний URL через API-клиент с авторизацией. Внешний source_url допускается только http/https и не является адресом API.

- 401 — токен отсутствует или недействителен.
- 403 — учётная запись не связана с HR-профилем.
- 404 — источник не существует, не опубликован, не проверен либо просрочен.
- 409 — запрошенная версия источника изменилась; нужно задать вопрос снова.
- 422 — неверный формат запроса.
- 503 — недоступен reader/хранилище, превышены лимиты, reader занят или снимок изменился во время ответа. Это техническая ошибка, не «ответа нет в базе».

Reader работает на `127.0.0.1:8081` или на `http://jana-reader:8081` при явном Docker opt-in, один запрос модели одновременно. В native-режиме по умолчанию 180 секунд, в Docker 300 секунд на HTTP-операцию reader; облачного fallback нет. Полная допустимая база должна помещаться в модельный контекст, статьи не обрезаются.

## Локальный демонстрационный мост

`examples.jana_local_demo` слушает127.0.0.1:8002 без настоящей Auth, читает только вымышленные JSONстатьи и предоставляет те же ask/sourceформаты. Vite proxy `/jana-demo` удаляет auth/cookie; он включается только в dev с `VITE_DEMO_JANA_PROXY=/jana-demo`. Не публикуйте этот demo API в Интернет и не монтируйте в production приложение.
