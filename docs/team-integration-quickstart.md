# Запуск общей сборки командой

Рабочая ветка: `codex/team-integration`. До её публикации на GitHub она доступна только в рабочей копии автора. После публикации: `git fetch origin`, затем переключитесь на эту ветку. Не объединяйте старые копии вручную поверх неё.

## Без общей Supabase

Следуйте [README](../README.md): установите Python/Node зависимости, подготовьте локальную Qwen, запустите reader8081, demo API8002 и Vite с `VITE_DEMO_JANA_PROXY=/jana-demo`. Выберите демо-режим в браузере. Данные сотрудников/заявок вымышленные, Jana отвечает настоящей локальной моделью по 13 новым статьям. Первый холодный запрос может занять заметно больше последующих; бюджет ожидания180сек.

Проверьте сотрудника, руководителя, директора и HR: первый этап согласования даёт pending_hr, окончательное HR решение даёт approved. Скачайте .ics окончательно одобренного отпуска и убедитесь, что включены обе даты. Откройте источник ответа Jana, задайте вопрос без подтверждённых сведений. Без model/demo API интерфейс должен показать недоступность, а не подставить готовый ответ.

Демонстрационный браузерный режим показывает интерфейс и локальную Jana; он не является проверкой серверной авторизации или настоящей общей БД. Серверные транзакции проверяются отдельно реальным локальным PostgreSQL.

## Сервер и миграции

Для новой изолированной PostgreSQL используйте полный `database/migration-plan.json`, а не сортировку файлов по именам. Исполняйте DB-тесты с `POSTTECH_TEST_DATABASE_URL` на loopback и именем `posttech_test_*`; они создают собственные одноразовые базы. `scripts/check_team_database.py` дополнительно проверяет полный bootstrap.

**Общую Supabase пока не менять.** К ней нельзя применять bootstrap нового проекта: в ветках различалась история миграций. После отдельного согласования требуется инвентаризация общей схемы и данных, план обновления, затем проверка настоящего Supabase Auth и общего сценария. Ключи остаются в приватном .env, в репозиторий и чат не попадают.

Текущее поведение: официальный остаток списывается при финальном HR одобрении ровно один раз. Google Calendar подключён ручным .ics, автоматической синхронизации нет. 1С/Documentolog без настроенных и проверенных получателей не являются готовыми интеграциями.
