# Запуск ветки test для команды

## Получить общий код

Сохраните свою незакоммиченную работу перед переключением ветки. Для новой отдельной копии:

```powershell
git clone --branch test https://github.com/Dmitribear/PostTech.git
cd PostTech
powershell -ExecutionPolicy Bypass -File scripts/start_docker.ps1
```

При NVIDIA GPU используется флаг `-Gpu`. Если GGUF уже есть, укажите `-ModelDirectory <каталог>` — файл проверится по SHA256 и скопируется в volume.

Откройте http://127.0.0.1:8000. Логины `employee@posttech.demo`, `manager@posttech.demo`, `director@posttech.demo`, `hr@posttech.demo`; пароль — значение `POSTTECH_DEMO_PASSWORD` в созданном `.local/docker.env`. У каждого участника свои локальные данные, ключи и пароль. Общий `.env` с ключами Supabase сюда переносить не нужно.

## Проверить общий сценарий

1. Войдите сотрудником, создайте отпуск на будущие даты.
2. Руководителем одобрите первый этап. Статус станет «Ожидает HR»; календарный файл ещё недоступен.
3. HR примите окончательное решение. Дни спишутся один раз; документ оформляется отдельным действием.
4. Сотрудником скачайте `.ics` в календаре. В Google Calendar импортируйте его вручную.
5. Нажмите Jana справа вверху, спросите «Кто окончательно одобряет отпуск?», откройте источник. Чат сохраняется при закрытии и переходах; при выходе из аккаунта очищается.
6. Проверьте неизвестный факт. Jana не должна придумывать ответ. Кнопка «Что требует внимания?» отдельно показывает доступную пользователю сводку портала.
7. Под руководителем создайте заявку и проверьте первый этап директором; директор не получает доступ ко всем сотрудникам автоматически.

Реальные тесты контейнерного API можно повторить локально:

```powershell
python scripts/check_docker_stack.py --scope core
python scripts/check_docker_stack.py --scope jana
```

Нужны Python-зависимости проекта. Скрипт использует только `.local/docker.env`, адрес 127.0.0.1 и локальные demo-аккаунты, создаёт явно помеченные заявки. Он не подходит для общей базы.

## Общая Supabase

В этой сборке общая Supabase не изменяется. Для будущего подключения сначала сравните историю миграций и подготовьте отдельный переход; не запускайте все bootstrap SQL поверх существующего проекта. В Docker свои PostgreSQL, Auth и REST. Почта локального стенда и реальные 1С/Documentolog не настроены.
