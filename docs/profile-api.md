# Личный кабинет сотрудника

`GET /api/v1/profile` возвращает кадровые поля текущего пользователя, краткие
сведения о его руководителе, назначенные курсы и последние уведомления одним
ответом. Существующие кадровые поля остаются на верхнем уровне JSON; новые
разделы называются `manager`, `assigned_courses` и `notifications`.

## Запрос и доступ

```http
GET /api/v1/profile
Authorization: Bearer <access_token>
```

Токен выдаётся `POST /api/v1/auth/login`. Сервер определяет сотрудника по токену:
параметры вроде `?employee_id=...` или `?user_id=...` не переключают владельца
профиля. Это правило действует для любой роли, включая `hr_admin`.

Официальные кадровые поля доступны сотруднику только для чтения. На экране
профиля показывайте текстовые значения без формы редактирования этих полей.
В ответе нет `auth_user_id`, пароля или токенов.

`manager` содержит только `id` и `full_name`. Этих данных достаточно для подписи
руководителя: дополнительно запрашивать его полный профиль не требуется.
Наличие `manager.id` в ответе не даёт сотруднику доступа к остальным персональным
данным руководителя.

## Девять элементов личного кабинета

| Элемент интерфейса | Поле ответа | Отображение |
| --- | --- | --- |
| Ф. И. О. | `full_name` | Имя сотрудника в заголовке. |
| Компания | `company` | Название компании. |
| Должность | `job_title` | Должность сотрудника. |
| Подразделение | `department` | Название подразделения. |
| Руководитель | `manager.full_name` | Имя руководителя; при `manager: null` — «Руководитель не указан». |
| Дата приёма | `hired_at` | Локализованная календарная дата, например `01.04.2025`. |
| Остаток отпуска | `vacation_days_remaining` | Число дней из ответа, включая дробную часть; `0` — корректное значение. |
| Назначенное обучение | `assigned_courses` | Название курса, статус, прогресс и результат, если он уже есть. |
| Уведомления | `notifications` | Заголовок, текст, дата и признак прочтения каждого уведомления. |

Дата `hired_at` имеет формат `YYYY-MM-DD` и обозначает календарный день, а не
момент времени. При форматировании не сдвигайте её из-за часового пояса.
`assigned_at`, `completed_at`, `created_at`, `updated_at` и `read_at` — временные
метки; их можно отображать в часовом поясе пользователя.

## Обучение и уведомления

`assigned_courses` совпадает по структуре с ответом
`GET /api/v1/academy/my-courses`: назначения идут от новых к старым по `assigned_at`.
Каждая запись содержит краткий объект `course`; материал курса и тест загружаются
при открытии через `GET /api/v1/academy/courses/{course_id}`.

Статусы обучения можно подписать так: `not_started` — «Не начат», `in_progress` —
«В процессе», `completed` — «Завершён». `progress_percent` отображается как
прогресс от 0 до 100. При `score_percent: null` результата ещё нет; значение `0`
означает полученный результат 0%, его нельзя заменять на «Нет результата».

`notifications` совпадает по структуре с `GET /api/v1/notifications`: до 100
последних уведомлений текущего сотрудника, от новых к старым по `created_at`.
При `read_at: null` уведомление не прочитано. Непустой `request_id` позволяет
открыть соответствующую заявку через `GET /api/v1/requests/{request_id}`.

Чтобы отметить уведомление прочитанным, используйте
`POST /api/v1/notifications/{notification_id}/read` с тем же Bearer-токеном.
После успешного ответа обновите запись на экране или перечитайте профиль.
Счётчик непрочитанных, вычисленный по этому массиву, относится только к
загруженным последним 100 уведомлениям.

## Пустые состояния и ошибки

- `manager: null`: покажите «Руководитель не указан» без вымышленного имени.
- `assigned_courses: []`: покажите «Назначенных курсов пока нет».
- `course: null` внутри назначения: покажите «Информация о курсе недоступна»;
  сохраните известный прогресс и не подставляйте чужой курс.
- `notifications: []`: покажите «Уведомлений пока нет».
- `score_percent: null`, `completed_at: null`, `assigned_by: null` и
  `request_id: null` — допустимые отсутствующие значения, а не ошибки загрузки.
- До получения ответа покажите состояние загрузки. При сетевой ошибке или
  ответе 5xx покажите ошибку с повторной загрузкой; не превращайте сбой в пустые
  массивы или демонстрационный профиль.
- `401`: токен отсутствует, истёк или недействителен; требуется восстановить
  сессию либо повторить вход.
- `403`: Auth-аккаунт не связан с кадровым профилем; нужна помощь HR/администратора.

Пустые массивы и `null` описывают реальные данные сотрудника. Они не означают,
что frontend должен создавать курсы, уведомления или кадровые сведения.

## Совместимость

`GET /api/v1/profile` дополняет прежние кадровые поля. Отдельные маршруты
`/academy/my-courses`, `/academy/courses`, `/notifications`, `/employees/{employee_id}`
и `/team` сохраняются с прежними правилами доступа. Запросы этих маршрутов
также используют префикс `/api/v1` и заголовок `Authorization: Bearer ...`.
Для показа своего кабинета достаточно одного `GET /api/v1/profile`.
