# Интерфейс объединённой ветки

React + TypeScript + Vite; интерфейс из `test` работает с объединённым API, локальной Jana и экспортом календаря из `Integration`. Правила ролей, заявок и базы описаны в [контракте backend](team-backend-contract.md), общий запуск — в [инструкции команды](team-integration-quickstart.md).

## Запуск

```powershell
npm ci --prefix frontend
npm run dev --prefix frontend
```

Портал открывается на `http://127.0.0.1:5173`. В обычном режиме браузер обращается к `/api/v1`; Vite перенаправляет `/api` на локальный backend `http://127.0.0.1:8000`. Для другого локального порта задайте `API_PROXY_TARGET` перед запуском Vite. Настройки Supabase и ключи моделей остаются на backend и не попадают в клиентские переменные `VITE_*`.

Демо выбирается явно на экране входа. Его сотрудники, заявки и обучение хранятся только в памяти вкладки и сбрасываются при перезагрузке. Ответы Jana не имитируются: для них требуется отдельно запущенный локальный сервер из `examples/jana_local_demo.py` на порту 8002 и точное значение перед запуском Vite:

```powershell
$env:VITE_DEMO_JANA_PROXY='/jana-demo'
npm run dev --prefix frontend
```

Этот мост доступен только в dev-режиме. Он передаёт вопросы и открытие источников локальному серверу без cookies и токенов портала. Без настройки моста ввод Jana в демо отключён; при недоступном сервере показывается ошибка. Учебная база демо не является утверждённой политикой JanaPost. Подробности запуска локальной модели — в [инструкции команды](team-integration-quickstart.md).

## Что сохранено в интерфейсе

- Вход, приглашение HR, подтверждение email и восстановление пароля; роли сотрудника, руководителя, директора и HR. Переключение роли возможно только в явном демо.
- Заявки, история, уведомления, календарь и остаток с учётом резервов. Руководитель переводит заявку в `pending_hr`, окончательное решение принимает HR. Сотрудник может отменить свою заявку до окончательного решения. Кнопки согласования учитывают `can_review` из API.
- Приглашения, делегирование первого этапа между руководителями/директорами, HR обращения, назначение обучения, материалы, сроки и попытки тестирования. HR не выбирается заместителем первого этапа.
- Полная страница Jana и виджет. Ответ содержит ссылки на материалы, точную цитату и непрозрачную версию источника. Материал загружается через авторизованный API; полученный текст не исполняется как HTML. Ошибку загрузки можно повторить. Изменившийся источник возвращает 409 с предложением задать вопрос заново.
- Уточняющий вопрос Jana не создаёт обращение. Передача в HR появляется при предложенной эскалации и требует отдельного действия пользователя.
- `.ics` доступен только у окончательно одобренного отпуска. Файл скачивается с авторизацией, после проверки `text/calendar`; Google Calendar импортирует его вручную. Это не постоянная синхронизация.
- Русский и казахский интерфейсы. Язык передаётся API; цитаты из документов сохраняются на языке оригинала.

## Проверка

```powershell
npm test --prefix frontend
npm run build --prefix frontend
npm run test:e2e --prefix frontend
```

Playwright проверяет настольный и мобильный экраны. Если Chromium не установлен, установите его для Playwright либо задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` к локальному Chrome/Edge. Чтобы использовать отдельно запущенный Vite, задайте `PLAYWRIGHT_BASE_URL`.

Браузерные проверки используют учебные данные и перехваченные HTTP-ответы. Они проверяют поведение клиента и контракт, но не заменяют проверки настоящего backend и миграций. `team-integration.spec.ts` покрывает два этапа согласования, роли заместителей, версии источников и календарь; `jana.spec.ts` — отказ, недоступную модель, повтор источника и ошибку экспорта после изменения статуса. Полный план локальной PostgreSQL-проверки приведён в [контракте backend](team-backend-contract.md). Общая Supabase для этих тестов не нужна и автоматически не меняется.

## Чат в верхней панели

Кнопка **Jana справа вверху** доступна после входа на страницах портала, включая полную страницу Jana. Она открывает модальное окно того же компонента: API, источники, версии, ошибки и согласие на передачу в HR общие. На экране входа кнопки нет.

Escape закрывает только верхнее окно: сначала источник или согласие HR, затем чат. Фокус остаётся внутри открытого окна и возвращается на кнопку после закрытия. Черновик, история и выполняющийся запрос сохраняются при закрытии и переходах между страницами в текущей сессии; выход или перезагрузка страницы очищают состояние.

«Что требует внимания?» отдельно читает авторизованную сводку `/workspace/summary`. Она помечена как данные портала и не отправляется в модель. Обычные вопросы Jana продолжают использовать только базу знаний. Из актуальной ветки `test` сохранены оформление HR, импорт сотрудников, планы адаптации, напоминания и оформление кнопок/списков.
