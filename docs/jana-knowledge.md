# Jana: ответы по текущему порталу

База `knowledge_base/demo/articles.json` содержит 18 статей о реализованных функциях PostTech. Она описывает интерфейс и ограничения портала, а не заменяет утверждённые корпоративные положения. Норма ежегодного отпуска, срок подачи заявления и график выплат не выводятся из демонстрационных остатков или примеров.

## Как формируется ответ

1. Отделяется информационный вопрос от запроса чужих данных, команды выполнить действие, посторонней темы или подмены инструкций. Смешанный запрос с посторонней задачей отклоняется целиком.
2. Модель выбирает подходящие по смыслу абзацы из опубликованных актуальных статей. Точное совпадение слов не требуется. Вопросы «хочу отдохнуть несколько дней» и «как оформить отпуск» ведут к одной процедуре.
3. Ответ ссылается на выбранные абзацы; отдельная проверка сверяет его с полными статьями, включая ограничения, которые могли потеряться при сокращении.
4. Критические условия отпуска и обучения дополнительно сверяются с текстом выбранных источников. Отрицания и отличие кадрового остатка от резерва нельзя заменять приблизительной формулировкой.
5. Сервер возвращает разрешённые идентификаторы кнопок. Их адреса задаются приложением, а права проверяются на сервере целевого экрана. Кнопки открывают формы; ответ ассистента не создаёт и не согласовывает заявки.

Выбор источников сейчас выполняется моделью по всему небольшому корпусу, без векторной базы. Предел — 100 статей и 60 000 символов. При превышении ответ не строится по молча обрезанной базе. Для роста корпуса потребуется индекс с версиями абзацев и семантическим отбором кандидатов; существующий формат источников и проверка полного текста сохранятся.

В OpenAI передаются вопрос и общие статьи. Персональные кадровые записи не добавляются к этому контексту. Ролевые сводки вычисляются отдельной серверной функцией. Запросы к модели используют `store=False`; это параметр запроса, а не заявление об отсутствии любого технического хранения у провайдера.

При недоступности генерации используется явно помеченная точная выдержка только при строгом совпадении темы и условий. Слабое совпадение не считается ответом. Просроченные статьи не используются. Открытие источника проверяет его версию: после обновления статьи пользователь получает предложение задать вопрос повторно.

## Обновление и проверка

Статьи публикуются через существующий процесс базы знаний: черновик → проверка → публикация. Обновление 18 октября 2026 года сохранило идентификаторы первых 11 статей и добавило ещё 7; публикация прошла с проверкой версий и сохранением истории. SQL seed предназначен для новых стендов, а не для перезаписи действующих редакций.

Регрессионный набор `evals/jana_portal_questions.json` содержит те же 49 вопросов, что исходная проверка. Ожидаются 29 подтверждённых ответов и 20 отказов. Дополнительный набор из 14 вопросов проверяет границы темы, смешанные запросы, приватность и русские/казахские формулировки. Автоматические проверки контролируют условия и кнопки, но не заменяют ручную оценку каждого ответа.

```powershell
.\.venv\Scripts\python.exe scripts/verify_jana_portal.py --report .local/jana-portal-check.json
.\.venv\Scripts\python.exe scripts/verify_jana_portal.py --transport http --base-url http://127.0.0.1:8000 --corpus evals/jana_portal_safety_questions.json --report .local/jana-safety-check.json
```

Проверка использует только маркированную тестовую учётную запись и не меняет кадровые данные. Итоговые результаты, отдельные повторные проверки и их происхождение сохраняются в [отчёте](performance/jana-portal-live-2026-10-18.json). Успех фиксированного набора не означает гарантированную точность любых будущих ответов.


## Казахский режим

Казахский вопрос проходит ту же проверку темы и доступа, что русский. Классификатор дополнительно возвращает русскую формулировку; исходный вопрос также передаётся генератору и проверке источников. Проверенный русский ответ переводится отдельным запросом без сокращения условий. После перевода сохраняются оговорка о необязательном сроке курса и отдельные отрицания об ограничении попыток и обязательной паузе — только при наличии соответствующего правила в выбранной статье. Названия кнопок и статусов согласованы со словарём интерфейса.

`JANA_KAZAKH_MODEL` позволяет отдельно настроить модель для казахских вопросов. На проверенном стенде используется `gpt-4.1`; русский режим остаётся на `OPENAI_MODEL=gpt-4o-mini`. При пустом параметре оба языка используют `OPENAI_MODEL`. Казахский запрос включает четыре обращения к модели: классификацию, ответ, сверку и перевод. Учитывайте это при выборе модели и расчёте расходов. Docker передаёт параметр из локального `.env`.

`evals/jana_kazakh_questions.json` содержит 26 вопросов: 22 объяснения функций и 4 отказа. Проверяются ограничения отзыва отпуска, возврат резерва без изменения кадрового остатка, запрет самосогласования, доступ к прямым подчинённым, необязательность комментария и срока обучения, проходной балл конкретного курса, пересдача и назначения ролей. Дополнительно сверяются все девять подписей навигационных кнопок с казахским словарём.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/verify_jana_portal.py --transport http --corpus evals/jana_kazakh_questions.json --report .local/jana-kazakh-check.json
```

Результаты проверки и её ограничения: [казахский режим, 18 октября 2026](performance/jana-kazakh-live-2026-10-18.json).


## Офлайн-FAQ

`knowledge_base/faq.json`, версия 1.1.0: 15 существующих тем сверены с текущими статьями портала. Карточки содержат точные цитаты, включая оговорки о правах, резервировании дней, необязательном сроке курса и проходном балле. Максимальная длина цитаты — 1000 символов: это позволяет сохранить условия целиком, без усечения. Схема отклоняет пустые и слишком длинные цитаты.

Контрольная сумма считается по всей исходной статье, даже если карточка цитирует только один абзац. Изменение условий в другом абзаце, снятие статьи с публикации или дублирующийся источник блокируют ответ до проверки карточки. Обновлять только хеш без смысловой сверки цитаты и всех вариантов вопросов нельзя.

Это ограниченный офлайн-каталог, а не копия всех возможностей генеративного режима. `unsupported_questions` задаёт границы именно этого каталога: наличие инструкции в общей базе не означает, что офлайн-поиск уже поддерживает соответствующий сценарий. При обновлении источников сначала проверяйте карточки и их варианты вопросов, затем хеши, проверки условий и отдельные контрольные вопросы. Старые отчёты сохраняют свои исходные версии и результаты.

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_jana_local.py tests/test_jana_evaluation.py -q
.\.venv\Scripts\python.exe -m scripts.check_jana_release --output-dir .local/jana-faq-release-check
```

Для второй команды нужны зависимости из `requirements-local-ai.txt` и модель, подготовленная `python -m scripts.prepare_jana_local`. После установки проверка работает на CPU без OpenAI и без обращения к базе сотрудников. Работающий портал переключать на локальный провайдер для такой проверки не требуется.

Проверка 18 октября 2026: прежние 14 падений устранены; полный серверный набор — 1257 успешно, 144 пропущены; настоящий офлайн-прогон — 285/285. [Отчёт с исходными ответами](performance/jana-faq-live-2026-10-18.json).
