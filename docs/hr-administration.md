# HR / администратор

В MVP роль `hr_admin` объединяет HR и администратора платформы. Она сохраняет
доступ к HR-сценариям и назначает роли существующим профилям сотрудников.

| Роль | Назначение |
| --- | --- |
| `worker` | Сотрудник: свой профиль, заявки, обучение и уведомления. |
| `manager` | Руководитель: свои данные и разрешённые данные прямых подчинённых. |
| `director` | Директор: свои данные и согласование заявок прямых подчинённых. |
| `hr_admin` | HR / администратор: HR-сценарии, список сотрудников и выдача ролей. |

## Подготовка

После миграций 0001–0003 выполните
[0004_hr_role_administration.sql](../database/migrations/0004_hr_role_administration.sql)
в SQL Editor Supabase. Она добавляет журнал `employee_role_changes` и транзакционную
функцию `assign_employee_role`. Миграция не назначает новых администраторов и не
меняет существующие роли. Повторное применение безопасно.

Для демонстрации `database/seed.sql` уже назначает `hr_admin` профилю
`hr@posttech.demo`. Auth-пользователь должен существовать до запуска seed.
Seed восстанавливает демонстрационные роли: не запускайте его как часть обычного
входа/старта сервера после ручного назначения ролей.

В базе без демонстрационных данных первого администратора назначает владелец
проекта в SQL Editor по проверенному UUID пользователя Supabase Auth:

```sql
update public.employee_profiles
set role = 'hr_admin'
where auth_user_id = '<UUID выбранного Auth-пользователя>'::uuid
returning id, full_name, role;
```

Профиль сотрудника должен уже существовать и быть связан с Auth-пользователем.
Если SQL не вернул строку, такой связи ещё нет. Публичная регистрация создаёт
только Auth-аккаунт: она не принимает роль и не выдаёт административные права.

## Выдача роли через API

1. Войти как HR/администратор через `POST /api/v1/auth/login`.
2. Получить сотрудников: `GET /api/v1/admin/employees?offset=0&limit=50`.
3. Отправить запрос с UUID **профиля сотрудника** из этого списка:

```http
PATCH /api/v1/admin/employees/<employee_id>/role
Authorization: Bearer <access_token HR-администратора>
Content-Type: application/json

{"role": "manager"}
```

Пример ответа:

```json
{
  "employee_id": "11111111-1111-4111-8111-111111111111",
  "previous_role": "worker",
  "role": "manager"
}
```

Допустимые значения: `worker`, `manager`, `director`, `hr_admin`.
При повторном назначении той же роли возвращается успешный ответ без повторной
записи в журнал. Идентификатор инициатора берётся сервером из текущей сессии,
его нельзя передать в JSON. Остальные поля профиля этим запросом не изменяются.

Новая роль действует со следующего API-запроса, включая запрос со старым ещё
действительным токеном: сервер каждый раз читает роль из базы. Интерфейс может
перечитать `GET /api/v1/profile`, чтобы обновить доступные разделы.

## Ограничения и ответы

- Без токена — `401`; сотрудник, руководитель и директор — `403`.
- Неизвестная роль, неверный UUID или лишние поля JSON — `422`.
- Несуществующий профиль — `404`.
- Администратор не может убрать собственную роль `hr_admin` — `409`.
- Руководителя с прямыми подчинёнными нельзя перевести в `worker`/`hr_admin`, пока
  ответственным способом не переназначены его подчинённые — `409`. Смена роли
  сама по себе не меняет `manager_id` и организационную структуру.
- При недоступной БД или неприменённой миграции 0004 — `503`.

Изменение роли и запись инициатора/старой/новой роли в журнал атомарны.
Одновременные назначения сериализуются, после ожидания права инициатора
проверяются повторно. Два HR не смогут одновременно понизить друг друга и
оставить систему без администратора. Прямое выполнение RPC из браузера
запрещено для `anon` и `authenticated`; функция доступна серверному `service_role`.

## Проверки

```powershell
python -m pytest tests/test_admin.py -q
python -m scripts.check_role_administration
```

Вторая команда требует Docker и образ `postgres:16-alpine`. Она создаёт временную
БД без открытых портов, внешней сети и постоянного тома, проверяет миграции,
права, откат при ошибке журнала и конкурентное взаимное понижение двух HR.
Тестовый контейнер удаляется в конце; Supabase и `.env` не используются.
