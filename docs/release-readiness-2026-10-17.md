# Готовность PostTech к демонстрации — 17 октября 2026

## Результат

Текущий Docker-стенд прошёл проверку UI/API/БД, реальную репетицию основных сценариев и проверку отдельной роли директора. Изменения направлены на воспроизводимость показа и корректность ответов, без добавления новых HR-модулей.

## Что исправлено

- Запуск Docker проверяет готовность Supabase после загрузки интерфейса. Отображение страницы больше не считается достаточным признаком готовности стенда.
- Добавлена read-only команда `scripts/check_release.py`: SPA-маршруты, readiness, недоступность профиля и календаря без авторизации, правильный 404 для отсутствующего ресурса.
- Добавлена реальная проверка назначения директора через HR, ограничений команды и маршрута личной заявки. Меняется только помеченная синтетическая учётная запись; её исходная роль восстанавливается.
- Старый сценарный тест приведён к текущим контрактам: HR-оформление отдельно от решения; сохранённый маршрут не пересчитывается при повторной отправке; заместитель сохраняет доступ к ранее рассмотренной им заявке.
- Нагрузочный сценарий применяет все миграции до 0016 и запускает оформление HR перед проверкой очереди, как это делает текущий продукт.
- Jana корректно обрабатывает вежливые вводные слова. До исправления дополнительный набор дал 8/12, после — 12/12. Смысловые ограничения неизвестного правила не удаляются, что закреплено отдельными тестами.
- Проверка AI принимает отдельный корпус, язык вопроса и проверяет открытие указанной версии источника.
- Обновлены текст защиты и инструкция запуска: резервы отпусков, редактор курсов, замещение, обращения в HR и три контейнера уже реализованы.

## Повтор перед защитой

```powershell
.venv/Scripts/python.exe scripts/check_release.py
.venv/Scripts/python.exe scripts/verify_jury_stand.py --base-url http://127.0.0.1:8000 --read-only
```

Полная репетиция изменяет только тестовые записи и сохраняет idempotency checkpoints:

```powershell
.venv/Scripts/python.exe scripts/verify_jury_stand.py --base-url http://127.0.0.1:8000
.venv/Scripts/python.exe scripts/verify_role_scenarios.py
.venv/Scripts/python.exe scripts/verify_director_live.py
.venv/Scripts/python.exe scripts/verify_workspace_live.py
.venv/Scripts/python.exe scripts/verify_hr_workflows_live.py
.venv/Scripts/python.exe scripts/verify_extensions_live.py
.venv/Scripts/python.exe scripts/verify_jana_quality.py
.venv/Scripts/python.exe scripts/verify_jana_quality.py --corpus evals/jana_release_questions.json --report .local/jana-extra.json
```

Ролевые репетиции и проверку директора запускайте последовательно: директор временно получает новую роль. Приватные учётные данные и отчёты с ID находятся в .local и не предназначены для публикации.
