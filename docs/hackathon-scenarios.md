# Демонстрация Challenge 02 — Digital HR

Критерии из предоставленного задания: сквозной сценарий — 30%, функциональность и UX — 20%, архитектура — 20%, AI Jana — 15%, Jana Academy — 10%, защита — 5%. Демонстрация строится вокруг одной истории сотрудника, а не перечня экранов.

## Проверка перед выступлением

Используйте только фиктивные аккаунты: сотрудник, его руководитель, HR и сотрудник другой команды. Пароли лежат в локальном приватном файле, не в презентации и не в Git. Участники и связь подчинения должны существовать в Supabase; переключатель демонстрационной роли не является реальным входом.

Проверьте готовность API, применённые миграции `0001`–`0004`, наличие трёх опубликованных учебных курсов и базы знаний. Базовый отпуск проверен через браузер и API, а расширенная матрица ролей, заявки, Academy и Jana — отдельным реальным API-прогоном: 266 вызовов, семь фиктивных аккаунтов, все 18 групп проверок пройдены. Конкретные результаты и границы записаны в [журнале проверки](live-verification.md). Новые изменения требуют своего фактического прогона.

## Сценарий на 6 минут

| Время | Действие | Что показать |
| --- | --- | --- |
| 0:00–0:40 | Вход сотрудника, главная и профиль | Его имя, роль, подразделение, руководитель, остаток отпуска; официальные сведения доступны только для чтения. |
| 0:40–1:40 | Создание отпуска или аванса | Заполнение, подтверждение, получатель согласования, номер заявки и история. Сохранённая заявка остаётся после обновления страницы. |
| 1:40–2:40 | Вход руководителя и решение | Только разрешённые заявки; решение с комментарием. После возврата сотрудника — новый статус, событие истории и уведомление. |
| 2:40–3:30 | Назначенный курс | Материал, сохранённый прогресс, отправка теста, результат. Правильные ответы не выдаются до отправки и не принимаются с клиента как итоговая оценка. |
| 3:30–4:30 | Вопрос Jana и источник | «Как оформить отпуск?» → подтверждённый фрагмент → открыть полный материал. «Сколько дней отпуска положено?» при отсутствии нормы в базе → отказ и HR. |
| 4:30–5:10 | Защита прав | Руководитель не открывает карточку чужой команды; сотрудник не становится HR из-за подмены роли в запросе. |
| 5:10–6:00 | Архитектура и границы | Показать [схему](architecture.md), реальные Supabase Auth/БД и честно обозначенные будущие 1С:ЗУП/Documentolog. |

На защите достаточно одного согласованного отпуска. Отказ, отмена, повтор теста и запросы без прав уже проверены через API в тестовом Supabase и могут быть дополнительными короткими сценариями, если остаётся время. Перед выступлением отдельно пройдите нужные действия через интерфейс.

## Подробные развилки и принятые решения

| Ситуация | Поведение прототипа |
| --- | --- |
| Работник входит | Личный профиль, свои заявки, назначенные курсы, свои уведомления; разделов управления нет. |
| Руководитель входит | Личный кабинет плюс очередь согласования и обучение непосредственных подчинённых. |
| HR входит | Собственный кабинет плюс сотрудники и их заявки/обучение. Чужие личные уведомления недоступны даже HR. |
| Аккаунт создан, профиль ещё не привязан | Вход в Auth не даёт кадровых прав. Портал объясняет необходимость связи с профилем. |
| Подмена роли в форме, токене или заголовке | Роль определяется кадровой записью на сервере. Клиентский выбор роли не повышает права. |
| Руководитель сам хочет в отпуск | Подаёт личную заявку; согласует вышестоящий руководитель либо HR. Своя заявка не появляется в его очереди согласования. |
| HR сам хочет в отпуск | Согласует подходящий руководитель либо другой HR. Самосогласование запрещено. |
| Руководитель отсутствует в оргструктуре или цепочка содержит цикл | Маршрут переходит к HR, исключая автора. Если никого нет — отправка недоступна, черновик можно сохранить. |
| Назначенный руководитель сам в отпуске | Автоматическое делегирование не включено. Другой HR может обработать чужую заявку; назначение временного заместителя требует отдельной политики. |
| Руководитель изменился после отправки | Сохранённые согласующие остаются видны в заявке. Доступ к полному профилю сотрудника отдельно следует текущей оргструктуре. |
| Работник передумал до решения | Отзывает pending-заявку с подтверждением. Сохраняются история и уведомления. |
| Отзыв и одобрение произошли одновременно | Блокировка строки допускает только один итог; второй участник получает актуальный статус/конфликт. |
| Заявка уже одобрена | Изменение дат и отзыв одобренного отпуска не выполняются задним числом. Нужен отдельный процесс корректировки через HR. |
| Руководитель отклоняет заявку | Обязательна непустая причина, доступная автору в истории и уведомлении. |
| Прошлые даты или пересечение своих активных отпусков | Сервер отклоняет заявку. Конец диапазона включён; соседние непересекающиеся периоды допустимы. |
| Двойной клик или потерянный ответ | Повтор с тем же ключом возвращает тот же результат, история и уведомления не дублируются. |
| Отпуск длиннее показанного остатка | Остаток — кадровый снимок, а не рассчитанный резерв. Условия и возможность отпуска проверяет человек; прототип не списывает дни и не рассчитывает будущие начисления. |
| Аванс | Положительная сумма в тенге, максимум 1 000 000 и два десятичных знака — техническая граница прототипа. Одобрение не запускает выплату. |
| Курс виден в каталоге, но не назначен | Работник видит описание; руководитель/HR может посмотреть материал и назначить курс допустимому сотруднику. Категория и аудитория — описание курса, не способ повышения прав. |
| Руководителю самому нужно обучение | Курс назначает вышестоящий руководитель или HR. Прохождение остаётся в личном разделе; командные результаты показаны отдельно. |
| Курс назначен повторно | Второе назначение возвращает конфликт; первое и его прогресс сохраняются. |
| Материал не изучен | Завершение теста недоступно до подтверждения изучения материала. Это отметка пользователя, а не измерение фактического чтения. |
| Результат ниже порога | Попытка и балл сохраняются, курс остаётся в процессе. Можно перечитать материал и повторить тест. |
| Порог достигнут | Фиксируются 100% прогресса, результат, дата и уведомления. Поздний прогресс или повторный тест не перезаписывают завершение. |
| AI нашёл источник | Показывает подтверждающий фрагмент и открываемый материал. |
| AI не знает правило или его просят принять кадровое решение | Сообщает об отсутствии подтверждения/своих полномочий и предлагает обратиться в HR. Передача вопроса в HR выполняется после просмотра текста и явного согласия; HR отвечает в портале. |

Настоящие кадровые правила — минимальный срок подачи, праздничные дни, переносы, превышение остатка, заместители и отзыв уже одобренного отпуска — требуют подтверждённой политики компании. Для них не придуманы юридические или финансовые последствия.

| --- | --- | --- |

| Обучение с понятным результатом | Получить недостаточный балл, повторить тест, увидеть две попытки и результат в кабинете руководителя. | Реализовано. Три новых содержательных курса по пять вопросов. |

| Предупреждение о нагрузке команды | Перед отпуском показывать руководителю число отсутствующих в нужные даты и минимальное покрытие смены, без медицинских причин коллег. Решение остаётся за человеком. | Идея после настройки реального графика и правил команды. |
| RU/KZ для настоящих сценариев | Перевести целиком вход → заявка → уведомление → курс, включая ошибки и материалы; не ограничиваться переключателем языка. | Реализован интерфейс RU/KZ и двуязычный проверочный курс. Старые материалы и источники без перевода показаны на русском с явной пометкой. |
| Прозрачность внешних интеграций | Карточка «когда обновлён кадровый снимок», затем номер и состояние документа из Documentolog. Неподключённые интеграции подписаны честно. | Архитектура описана; промышленных подключений нет. |

Для защиты лучше пройти один цельный сюжет и две сложные развилки за 6 минут. Эффект измерять на демонстрации: число шагов, время от подачи до понятного результата, отсутствие дублей и отказ в чужом доступе. Не обещать выдуманные проценты экономии и не выдавать тестовые правила за утверждённую политику компании.


## UX-аудит по ТЗ от 17 октября 2026 года

Основание: раздел Digital HR, страницы 13–19 файла «Jana_Post_Terricon_Hackathon_2026 1.pdf». Требование — минимальное число понятных шагов, а не фиксированный лимит в три клика. Промышленные 1С:ЗУП/Documentolog, ЭЦП и нативное приложение не входят в обязательный MVP; показать архитектурное место интеграций обязательно.

### Как считали

Начало — уже загруженная главная после входа, без открытых диалогов. Один клик/тап на кнопку, ссылку, ответ теста, поле или флажок — одно действие. Ввод символов, чтение, ожидание сети и прокрутка не включены в число кликов, но остаются частью работы. Даты выбираются в видимом месяце: каждый переход месяца добавляет клик. Нет необязательных комментариев, исправлений, ошибок и повторов. Для суммы учтён один клик фокуса поля. Это замер конкретного маршрута, а не среднее по пользователям или гарантированное время выполнения.

«Было» — исходный UI Docker до изменения. Отпуск (7 кликов) и верхний маршрут обучения (2 клика до материала) пройдены в браузере; остальные исходные цепочки сверены по исходному интерфейсу и обработчикам. «Стало» для отпуска, аванса, согласования, обучения и назначения проверено действиями в браузере на реальном Supabase, с вымышленными аккаунтами. Ширины: 1280 px и 390 px. Числа для неизменённых вспомогательных путей ниже рассчитаны по действующим экранам.

| Задача и выбранный маршрут от главной | Было | Стало | Условия |

Три клика для отпуска возможны только при исключении двух выборов дат из счёта: открыть → продолжить → отправить. Полное число физических нажатий — пять. Для курса нельзя считать ответы на вопросы и чтение «лишними»: оптимизирован вход в материал, а не сам факт обучения.

### Что изменено

- Отпуск с главной, из профиля и сервисов ведёт сразу в существующий календарь диапазона. Ручной ввод, проверка пересечений и возможность исправить период остаются.
- Убрано повторное «Данные верны» после уже показанной сводки. Отправка по-прежнему отдельная и явная; двойные запросы защищены прежними ключами повторной отправки.
- Аванс доступен на главной. Заявки остаются в боковой/нижней навигации и блоке последних заявок.
- Верхняя карточка обучения ведёт непосредственно в ближайший по сроку незавершённый назначенный курс; без сроков — в начатый курс. Учитываются назначенные архивные версии, завершённые не предлагаются повторно. Весь каталог остаётся в разделе обучения.
- В рабочей очереди руководителя/HR показаны до трёх конкретных разрешённых заявок. Собственные заявки исключены. В карточке комментарий сотрудника и блок решения теперь идут перед историей.
- В небольшом каталоге назначение курса не требует раскрывать отдельное меню.
- Под подтверждёнными ответами Jana на готовые вопросы есть переход к соответствующему действию. Отказ не получает кнопку, создающую впечатление разрешённого кадрового решения.

### Что добить дальше

1. Обновить шестиминутную демонстрацию и слайды под текущие сценарии и реальные числа кликов. Это более прямое попадание в критерии, чем новые необязательные модули.
2. Дать HR проверить и датировать реальные регламенты; подготовить проверенные казахские материалы. Не приписывать демонстрационным источникам статус утверждённых.
3. Отдельно проверить длинные HR-формы и большой каталог/штат на телефоне: поиск, создание курса, приглашения. Для массовой работы полезны фильтры и групповые назначения, но не ценой проверки прав.
4. Для следующего продуктового этапа — адаптеры 1С/Documentolog, синхронизация баланса, повторные попытки обмена и наблюдение за ошибками. В оценке MVP отсутствие промышленных подключений само по себе не штрафуется.

### Проверка изменений

Production-сборка и Docker-сборка прошли. 31 тест фронтенда и 67 целевых серверных тестов прошли. Повторная проверка живого стенда `verify_jury_stand.py --read-only` прошла для всех трёх ролей. Существующие Playwright-спецификации обновлены под явную отправку без дополнительного флажка; полный автоматический E2E-набор в этом прогоне не запускался. Изменённые сценарии пройдены через браузер на настоящем Supabase. Переход из подтверждённого ответа Jana в выбор дат проверен одним кликом. Результат обучения — 100%, новая попытка сохранена.
