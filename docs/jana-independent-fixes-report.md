# Jana: исправления после независимых 50 вопросов

Проверено 17 октября 2026 года. Исходный независимый набор после первого прогона стал известен разработчикам; нынешняя проверка — регрессия на тех же вопросах, а не новая независимая оценка.

Исправлены оба неверных ответа и все 18 лишних отказов первого прогона. Ответы остаются дословными выдержками из опубликованных статей со ссылками на источники. Сами статьи, вопросы, ожидаемые результаты и первоначальные отчёты не изменены.

## Результат

| Проверка | До исправлений | После исправлений |
| --- | ---: | ---: |
| Старые 285 случаев: проверка карточки, цитаты и контракта | 285/285 | 285/285 |
| Новые 50: прежняя автоматическая проверка | 30/50 | 49/50 |
| Новые 30 вопросов с ответом в базе: содержательная полнота | 10/30 | 30/30 |
| Новые 20 случаев с ожидаемым отказом: безопасное поведение | 20/20 | 20/20 |
| Лишние отказы среди новых 30 поддержанных вопросов | 18 | 0 |
| Неподходящие фактические ответы среди новых 30 вопросов | 2 | 0 |

Локальные результаты подтверждены через Vite → FastAPI → общую Supabase. HTTP-проверка использует реальный вход тестового сотрудника, проверяет недоступность AI и источников без авторизации, получает опубликованные статьи и сравнивает полные ответы. Это проверка API фронтенда; визуальные действия в браузере в этом прогоне не повторялись.

Первый HTTP-прогон старых наборов с двумя параллельными потоками оказался незавершённым: 203/285 ответов получены и прошли проверку, четыре набора остановились на HTTP 503. Отчёт сохранён в `final-http` с `complete=false`, кодом выхода 2 и деталями остановок. После этого реальный вход и восемь последовательных запросов снова прошли; причина временного сбоя не установлена. Итоговый полный прогон выполнен отдельно, последовательно, в `final-http-sequential`, без автоматического повторения отдельных запросов. Это ограничение доступности сервиса нельзя скрывать за результатом проверки содержания.

**Почему автоматический результат 49/50:** A04 спрашивает, чьего рассмотрения ожидает заявка на отпуск в статусе pending. Замороженная разметка ожидает `request_status`, но прямая фраза «ожидает рассмотрения руководителем сотрудника или HR» находится в статье об отпуске, карточке `leave_apply`. Теперь Jana возвращает именно эту подтверждённую цитату. Идентификатор не совпадает с ожиданием, поэтому старый оценщик честно сохраняет `wrong_card` и код выхода 1. Разметка и оценщик ради результата не исправлялись; содержательная проверка учитывает этот случай отдельно.

20 безопасных отказов не означают 20 полностью полезных ответов. Часть отказов остаётся общей: Jana не всегда задаёт конкретный уточняющий вопрос или объясняет, какого факта нет. Содержательная проверка перечисляет эти ограничения. Результат также не гарантирует точность на любых будущих формулировках.

## Что изменено

- Расширены 7 коротких выдержек: сумма и даты отпуска, рассматривающие роли, отсутствие банковского перевода, права доступа, назначение и завершение курсов, уведомления, включение последнего дня в календарь. Все выдержки — непрерывные фрагменты прежних статей, не более 500 символов.
- Сохранены прежние поисковые формулировки, добавлены примеры недостающих намерений. Теперь 196 примеров, максимум 20 на карточку. Дословных совпадений с 335 проверочными вопросами нет.
- Несовместимая по смыслу карточка исключается до сравнения уверенности: например, синхронизация календаря не отвечает на вопрос о допустимости дат в форме отпуска. Отрицательные примеры сохраняются, пороги 0,72 и 0,045 не снижены.
- Связанные шаги одной формы и короткое пояснение после вопроса не вызывают лишний отказ. Вопросы о разных объектах по-прежнему разделяются.
- Добавлены ограниченные исправления опечаток. Имена, адреса, числа и отрицания сохраняются; максимум две правки.
- Явно ограничены запросы текущего решения по личной заявке и содержимого кадровой карточки. Команды отмены и удаления распознаются как действия.
- Проверка полного SHA-256 статьи, активности и единственности источника сохранена. После ошибки источника другой ответ не подставляется.

## Проверки и воспроизведение

Финальный backend: **524 passed, 37 skipped**. Пропущенные тесты требуют отдельной PostgreSQL-базы для проверки workflow; они не запускались против общей командной базы. Интерфейс, схема API и статьи Supabase в этой доработке не менялись.

Из корня проекта, с установленной локальной моделью и зависимостями:

```powershell
python -m scripts.check_jana_release --output-dir .venv/jana-repeat-old
python -m scripts.evaluate_jana_local --cases knowledge_base/demo/independent_agents_v1.json --output .venv/jana-repeat-50.json
python -m scripts.evaluate_jana_http --credentials-file .venv/supabase-integration-accounts.json --cases knowledge_base/demo/independent_agents_v1.json --output .venv/jana-repeat-50-http.json
python -m pytest -q
```

Для HTTP нужны запущенные backend на порту 8000, frontend на 5173 и локальный файл учётных данных тестового сотрудника. Он не входит в Git; пароли и токены в отчётах отсутствуют. Для новых прогонов выбирайте новые имена файлов. У набора 50 ожидается единственный описанный выше `wrong_card` A04; это не скрытый успешный код выхода.
