## Итоговая сборка

Jana открывается кнопкой справа вверху, включая мобильный экран. Чат сохраняет историю при закрытии и переходах, очищается при выходе из аккаунта. Источник показывает исходную цитату и проверенную версию. Оперативная сводка использует отдельный endpoint и серверные права; персональные записи не передаются модели.

В Docker работают frontend, API, отдельный Jana reader, PostgreSQL, GoTrue Auth, PostgREST, gateway и workflow-worker. Модель Qwen3.5-9B Q4_K_M проверяется по SHA256 и сохраняется в volume. Снаружи опубликован только frontend на 127.0.0.1:8000; API, модель и база находятся в закрытой сети. Для публикации порта Docker Desktop frontend дополнительно подключён к edge-сети.

Локальный bootstrap применил 18 миграций, создал четыре демонстрационных аккаунта и 17 опубликованных демо-статей. Сохранены директор, права непосредственного руководителя, этап pending_hr, однократное списание отпуска, отдельное оформление документа и закрытие резерва. Внешняя отправка в 1С/Documentolog требует отдельной настройки приёмников и явного действия HR.

Календарь берёт отпуска из той же базы проекта. Индивидуальный и общий .ics предназначены для ручного импорта в Google Calendar. Экспорт включает только approved leave, сохраняет обе крайние даты и не обещает автоматического обновления импортированных событий.

## Ограничения

Это локальный стенд с вымышленными данными, а не изменение рабочей Supabase. Email подтверждается автоматически только для локального демо; настоящая почта, Google OAuth, 1С и Documentolog не подключены. Файл .ics обновляется вручную, повторный импорт может дать дубликаты. Общая база потребует отдельного плана перехода; manifest для новой локальной базы нельзя запускать вслепую поверх существующего проекта.

Модель работает на оборудовании компьютера; первый ответ может быть заметно медленнее повторного. Проверка точной цитаты и актуальной версии защищает происхождение ответа, но сама по себе не доказывает его смысловую релевантность. Для демонстрации используйте проверенные сценарии и открывайте источники.

Запуск: [инструкция команды](team-integration-quickstart.md), [Docker](docker-local.md), [архитектура](architecture.md).

## Параллельное обновление main

При финальном fetch обнаружен новый `main` 268a7e2: отдельная параллельная реорганизация проекта в Clean backend и FSD frontend. Эта поздняя перестройка не включена в проверенную сборку test; объединённые выше функции директора и HR из main55f5c09 сохранены. Новый main остаётся нетронутым на GitHub. Его перенос потребует отдельной сверки переименованных модулей, схемы БД и повторной проверки, а не автоматической замены работающей сборки.

Отдельный аудит уникального 268a7e2 подтвердил: новые дополнения — курсорная пагинация `/team/page`, индексы и структура слоёв. При этом новая main использует другой процесс одобрения: переход сразу в approved без немедленного изменения официального остатка. Автоматический перенос этих SQL изменил бы проверенную двухэтапную цепочку с окончательным решением HR. Поэтому это отдельное решение команды, а не пропущенный конфликт слияния.
