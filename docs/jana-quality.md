# AI Jana: проверка пункта 4

## Генерация и мобильный HR — 17 октября 2026

Добавлен режим `generated`: модель формулирует короткий ответ по найденным статьям, возвращает точные подтверждающие цитаты, после чего отдельный вызов проверяет ответ по этим цитатам. Проверяются принадлежность цитат источникам, новые числа, посторонние URL, запрещённые кадровые действия, отказ модели и незавершённый ответ. Эта проверка моделью снижает риск, но не доказывает фактическую корректность; HR всё ещё должен утвердить сами материалы.

Используется существующая настройка `OPENAI_MODEL` (по умолчанию `gpt-4o-mini`), серверный `OPENAI_API_KEY` и [Structured Outputs OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat). Форма JSON контролируется схемой; сама схема не проверяет истинность утверждений. В запросах отключено сохранение через `store=False`; персональные кадровые таблицы модели не передаются. Это не обещание отсутствия хранения провайдером по его другим правилам.

Без ключа или при сбое остаётся явно обозначенная цитата (`mode=excerpt`). Для диагностики возвращается только безопасная категория причины, без ключа, тела ошибки провайдера и кадровых данных. Для отказа — `mode=refusal`. Казахский интерфейс запрашивает краткий ответ на казахском; цитаты и источники остаются на исходном языке. Свободные казахские вопросы по-прежнему ограничены текущим поиском базы; четыре готовых вопроса нормализуются.

Проверка именно живой генерации, а не резервного режима:

```powershell
.\.venv\Scripts\python.exe scripts/verify_jana_quality.py --base-url http://127.0.0.1:8000 --credentials .local/jury-credentials.json --require-generation --report .local/jana-generation-report.json
```

Ключ следует сохранить только в локальном `.env`, затем пересоздать контейнер через `Start PostTech Docker.cmd`. Секрет нельзя добавлять в `VITE_`-переменные или отправлять в чат. На момент подготовки изменений ключ отсутствовал; факт подключения и результаты реального запроса должны быть отмечены отдельно после сохранения ключа. Успешные тесты с подменой модели не подтверждают доступ к OpenAI.

Новые проверки включены в `tests/test_jana.py`; совместный прогон с запросами, HR API и вебом: 135 тестов прошли.

## Предыдущий прогон поиска цитат

Дата: 17 октября 2026, UTC+5. Стенд использует настоящий Supabase.

В `evals/jana_questions.json` находятся 30 фиксированных вопросов: 16 ожидаемых ответов по источникам и 14 отказов. Проверяются обычные формулировки, синонимы, отсутствующие правила, вопросы вне базы, персональные данные, подмена инструкций и запросы кадрового решения.

Ответ считается прошедшим проверку, если совпадают ожидаемые признаки `grounded` и `escalation_suggested`, присутствует ожидаемый источник, его карточка доступна и содержит метаданные актуальности. Для отказов источников быть не должно. В модульных тестах приватные запросы дополнительно проверяются на отказ до обращения к базе и модели.

Результат реального прогона: **30 из 30**. Это результат подготовленного набора, а не универсальная оценка точности. На стенде наблюдался резервный ответ точной цитатой при недоступности AI-генерации. Работа внешней модели этим результатом не подтверждается.

Изменения: нормализация ограниченного набора синонимов, покрытие вопроса отдельным источником до вызова модели, запрет персональных запросов, метаданные версии/обновления/проверки. Источники с просроченной проверкой исключаются из ответов. Изменение текста сбрасывает прежнее подтверждение проверки на уровне базы. Миграция 0006 применена в Supabase и проверена отдельным PostgreSQL-тестом.

Резервный ответ показывает один наиболее релевантный источник, чтобы не перегружать ответ соседними темами. Политики компании и автоматический процесс их проверки ещё должны быть предоставлены HR. Передача вопроса в HR реализована с предварительным просмотром текста и явным согласием пользователя; ответ HR и уведомление проверены на реальном Supabase (этапы 7–10).

Финальный повторный прогон после сокращения резервного ответа: **30/30**. При проверке учитывается самостоятельная статья «Статусы заявок» как прямой источник для вопросов о статусе, наряду с общим порядком отпуска. У статьи о статусах уточнено, что в карточке показывается комментарий рассмотревшего заявку руководителя или HR; это соответствует реализованному сценарию и проверенному экрану. Обновление демонстрационной статьи сохранено в `database/seed_knowledge_status.sql`, версия 2, без фиктивной даты HR-проверки. На новом стенде примените этот файл после основной демонстрационной базы и миграции 0006.

Повторный запуск:

```powershell
.\.venv\Scripts\python.exe scripts/verify_jana_quality.py --base-url http://127.0.0.1:8010 --credentials .local/jury-credentials.json
```

Отчёт сохраняется в `.local/jana-quality-report.json`. В нём нет паролей, сессий или ответов с персональными данными. Для добавления нового вопроса внесите ожидаемый исход в корпус и проверьте его отдельно; не расширяйте допустимые ответы только ради прохождения теста.
