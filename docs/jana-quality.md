# AI Jana: проверка пункта 4

Дата: 17 октября 2026, UTC+5. Стенд использует настоящий Supabase.

В `evals/jana_questions.json` находятся 30 фиксированных вопросов: 16 ожидаемых ответов по источникам и 14 отказов. Проверяются обычные формулировки, синонимы, отсутствующие правила, вопросы вне базы, персональные данные, подмена инструкций и запросы кадрового решения.

Ответ считается прошедшим проверку, если совпадают ожидаемые признаки `grounded` и `escalation_suggested`, присутствует ожидаемый источник, его карточка доступна и содержит метаданные актуальности. Для отказов источников быть не должно. В модульных тестах приватные запросы дополнительно проверяются на отказ до обращения к базе и модели.

Результат реального прогона: **30 из 30**. Это результат подготовленного набора, а не универсальная оценка точности. На стенде наблюдался резервный ответ точной цитатой при недоступности AI-генерации. Работа внешней модели этим результатом не подтверждается.

Изменения: нормализация ограниченного набора синонимов, покрытие вопроса отдельным источником до вызова модели, запрет персональных запросов, метаданные версии/обновления/проверки. Источники с просроченной проверкой исключаются из ответов. Изменение текста сбрасывает прежнее подтверждение проверки на уровне базы. Миграция 0006 применена в Supabase и проверена отдельным PostgreSQL-тестом.

Резервный ответ показывает один наиболее релевантный источник, чтобы не перегружать ответ соседними темами. Политики компании и автоматический процесс их проверки ещё должны быть предоставлены HR. Автоматическое создание обращения в HR относится к следующему этапу.

Финальный повторный прогон после сокращения резервного ответа: **30/30**. При проверке учитывается самостоятельная статья «Статусы заявок» как прямой источник для вопросов о статусе, наряду с общим порядком отпуска. У статьи о статусах уточнено, что в карточке показывается комментарий рассмотревшего заявку руководителя или HR; это соответствует реализованному сценарию и проверенному экрану. Обновление демонстрационной статьи сохранено в `database/seed_knowledge_status.sql`, версия 2, без фиктивной даты HR-проверки. На новом стенде примените этот файл после основной демонстрационной базы и миграции 0006.

Повторный запуск:

```powershell
.\.venv\Scripts\python.exe scripts/verify_jana_quality.py --base-url http://127.0.0.1:8010 --credentials .local/jury-credentials.json
```

Отчёт сохраняется в `.local/jana-quality-report.json`. В нём нет паролей, сессий или ответов с персональными данными. Для добавления нового вопроса внесите ожидаемый исход в корпус и проверьте его отдельно; не расширяйте допустимые ответы только ради прохождения теста.
