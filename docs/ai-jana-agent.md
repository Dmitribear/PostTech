# Jana в объединённой ветке

Вызов `/api/v1/ai/ask` требует Bearer-авторизации и связанного HR-профиля. Он читает только общие `knowledge_articles`. Модель Qwen3.5-9B Q4_K_M работает через llama.cpp на loopback или в отдельном Docker-контейнере, без платного API и без облачного fallback. Она получает вопрос и полный допустимый снимок статей, выбирает намерение и идентификаторы предложений. Сервер возвращает точные цитаты и собственные фиксированные пояснения. Модель не исполняет действия, не читает профили или заявки.

Допускаются активные опубликованные/legacy статьи с прошедшей проверкой и неистёкшим сроком актуальности. Черновики, архив и непроверенные статьи исключаются. Содержание не обрезается: если полный снимок не помещается в лимит, API возвращает 503. После inference снимок перечитывается; изменение базы во время ответа также даёт 503.

Каждая ссылка содержит непрозрачный токен версии снимка. `/ai/sources/{id}?version=...` возвращает 409, если источник изменился, и 404 для недоступного источника. Поле `grounded` означает наличие подтверждённой цитаты, но не доказывает, что модель выбрала её правильно. При просьбе уточнить вопрос `escalation_suggested=false`; обращение в HR создаётся только отдельным явным действием пользователя с согласием.

Оригинальный язык текущих статей — русский. В казахском интерфейсе это явно указано; цитаты не переводятся неподтверждённой генерацией. Каждый вопрос независим, памяти разговора нет.

Текущие знания находятся в `knowledge_base/demo/articles.json` (17 статей): два этапа согласования, списание отпуска, приглашения, Academy с проходным баллом, HR обращения, версии источников и ручной .ics, оформление документов, импорт, планы адаптации и напоминания. Это описание демо, не кадровая политика Jana Post. `knowledge_base/faq.json` и исторические acceptance-наборы сохранены для аудита старого механизма, но рабочая Jana их не загружает.

`examples.jana_local_demo` использует тот же reader на вымышленных статьях и локально формирует .ics. Запускать только на 127.0.0.1, не монтировать в производственный API. Порядок запуска указан в README.

Известная граница: на предыдущих 50 независимых вопросах до объединения было 28 полных ответов, 8 частичных и 14 ошибок. Обновление знаний не превращает этот показатель в гарантию. Проверки интеграции и транзакций считаются отдельно от качества понимания языка.

Кнопка справа вверху открывает сохраняющий состояние модальный чат. Отдельная кнопка оперативной сводки читает `/workspace/summary` с проверкой роли, без LLM. При выходе из аккаунта история окна очищается. Запуск контейнеров описан в [Docker](docker-local.md).
