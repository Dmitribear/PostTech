# Jana: локальное понимание вопросов и ответы по всей базе

Рабочий `POST /api/v1/ai/ask` использует **Qwen3.5-9B локально через llama.cpp**.
Модель читает вопрос и все опубликованные статьи, определяет намерение и выбирает
подтверждающие предложения. Сервер возвращает дословные цитаты и ссылки.
Фактический текст ответа модель не сочиняет. FAQ-примеры и тестовые вопросы
в её контекст не передаются, обучение на них не выполняется.

Основной запуск — Windows x64, reader, FastAPI и Vite на одном компьютере.
[Инструкция команды](team-integration-quickstart.md), [контракт API](ai-jana-api.md),
[актуальная схема](architecture.md).

## Подготовка и запуск

После установки Python 3.12 и зависимостей из `requirements-dev.txt`, из корня проекта:

```powershell
python -m scripts.prepare_jana_reader
powershell -File scripts/start_jana_reader.ps1
Invoke-RestMethod http://127.0.0.1:8081/health
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Используйте Python своего окружения: например, `.\.venv\Scripts\python.exe`;
на исходном компьютере — `.\.venv\runtime\Scripts\python.exe`.
Скрипт запускает модель скрытым фоновым процессом. Дождитесь успешного `/health`.
PID и журналы: `.models/reader/server.pid`, `server.out.log`, `server.err.log`.
При занятом 8081 повторный запуск завершается сообщением: используйте уже работающий
экземпляр либо явно остановите свой процесс после проверки PID.

Подготовка загружает Qwen3.5-9B `Q4_K_M` (около 6,17 ГБ) и Windows x64 Vulkan
runtime llama.cpp (архив около 32 МБ). Версии, размеры, SHA-256 и лицензии закреплены
в [reader-model.json](../knowledge_base/reader-model.json). Файлы находятся в
`.models/reader`, исключённой из Git. Повторная проверка без сети:

```powershell
python -m scripts.prepare_jana_reader --verify-only
```

Исходные веса — Qwen/Qwen3.5-9B; используемая GGUF-квантизация опубликована
участником сообщества bartowski. Это не официальный GGUF-файл от Qwen.
В манифесте отдельно закреплены происхождение, ревизия и контрольная сумма конверсии.
Используется только текст; компонент обработки изображений не загружается.

Конфигурация выбрана под Intel i5-9400F, 16 ГБ RAM и GeForce GTX 1650 SUPER
с 4 ГБ VRAM. Весь файл весов в такую видеопамять не помещается: на GPU перенесены
20 слоёв, остальные используют RAM/CPU. Манифест задаёт контекст 8192 токена,
четыре потока и один одновременный запрос. Свободная RAM и видеопамять влияют
на доступность и скорость; это ориентир для конкретного компьютера, а не гарантия
производительности на любом устройстве. Для CPU предусмотрен `-GpuLayers 0`.
Параметры по умолчанию скрипт берёт из актуального манифеста.

## Как формируется ответ

1. FastAPI проверяет Supabase-сессию и наличие HR-профиля. Сведения профиля в модель не передаются.
2. API читает **все активные** общие статьи `knowledge_articles`. Проверяются UUID,
   уникальность и размер набора. Предложения получают ID, зависящие от полного содержимого статьи.
3. Модель получает полный вопрос и предложения, сгруппированные по источникам.
   Сначала она кратко формулирует намерение для внутренней проверки; этот текст
   пользователю не показывается. Затем выбирает тип ответа и ID: ответ, частичный ответ, отсутствие сведений,
   уточнение, просьба выполнить действие, запрос личных данных или обход ограничений.
4. Сервер проверяет JSON, лимиты и каждый ID по текущему снимку опубликованных
   источников. Ответ собирается из утверждённых вводных фраз
   и точных подстрок источников. Разделённые фрагменты одной статьи объединяются
   с промежуточным контекстом; ссылка одна на статью.

Это один проход языковой модели. Серверная проверка подтверждает целостность
источников и точность цитирования, но не определяет, правильно ли выбран смысл.
Последнее проверяется отдельной оценкой ответов по заранее зафиксированным фактам.

Несколько предложений в вопросе сами по себе не вызывают отказ. Jana отличает
общие правила от просьбы прочитать личную запись или выполнить действие.
Инструментов чтения профилей, SQL и изменения данных у модели нет.
Памяти диалога нет: контекст разрешается только внутри текущего вопроса.

Недостаток сведений даёт отказ или частичный ответ с рекомендацией обратиться в HR.
Неясный вопрос получает уточнение. Сбой модели/базы или превышение полного контекста —
HTTP 503. Неверный формат выбора/ID даёт безопасный отказ.
Автоматического переключения на платный API или mock нет.

`grounded=true` подтверждает происхождение цитат. Модель может неверно понять вопрос,
выбрать недостаточный фрагмент или лишний раз отказаться. Проверка источников
не обеспечивает 100% смысловой точности.

## База знаний и пределы

Сейчас демо содержит 11 вымышленных статей из
[articles.json](../knowledge_base/demo/articles.json); рабочий API читает Supabase.
Новая активная статья доступна при следующем запросе без FAQ-карточки, списка
формулировок и переобучения. Изменение текста меняет ID фрагментов; отключение
статьи исключает её из нового снимка. Открытие источника читает актуальную статью отдельно.

Публикуйте только одобренные общие материалы: они доступны всем вошедшим сотрудникам
с HR-профилем. Закрытые HR-документы и личные записи сюда не относятся.
Наличие цитаты не подтверждает истинность корпоративного документа.

Бюджеты: 100 статей, 20 000 символов в статье, 48 000 суммарных символов текста
с заголовками и 64 000 символов подготовленного контекста. Дополнительно сервер
считает **реальные токены** шаблона и оставляет резерв для ответа.
Большая база не обрезается: API сообщает о техническом ограничении.
Для её роста понадобится отдельная проверенная схема поиска и ранжирования.

Вопрос: 3–2000 символов. Выбор: до восьми фрагментов; суммарные цитаты с
промежуточным контекстом — до 2400 символов. Одновременно выполняется один запрос;
занятость может дать 503. Нагрузка всей компании ещё не проверена.

Общий Supabase уже подготовлен: повторно выполнять seed не нужно.
Для отдельной новой демо-базы `python -m scripts.export_jana_demo` генерирует SQL,
но сама команда ничего не пишет в Supabase.

## Настройки и стоимость

```dotenv
JANA_READER_URL=http://127.0.0.1:8081
JANA_READER_MODEL=jana-reader
JANA_READER_TIMEOUT_SECONDS=120
```

Разрешён только loopback; прокси окружения и редиректы не используются.
При обработке вопроса файлы не скачиваются и платный AI API не вызывается.
Лицензии Qwen — Apache-2.0, llama.cpp — MIT; закреплённые ссылки есть в манифесте.
Платы за токены нет. Компьютер, электричество, обслуживание и Supabase остаются
отдельными затратами и зависимостями. Интернет нужен для Supabase Auth и данных.

**Docker:** текущий Compose запускает API, но не reader. Loopback контейнера не
является loopback Windows-хоста; клиент Jana запрещает удалённый адрес модели.
Полный запуск через существующий Compose не настроен. Используйте нативный запуск.

## Проверка качества

При запущенном reader:

```powershell
python -m pytest -q -p no:cacheprovider
python -m scripts.evaluate_jana_reader --mode local --cases knowledge_base/demo/independent_agents_v2.json --development --output .venv/jana-reader-dev-01.json
```

Это разработка на известном наборе, не слепая проверка. Для нового независимого
набора сначала фиксируются код и ожидаемые факты, затем используется
`--runtime-freeze <файл>` без `--development`. HTTP-режим
`--mode http --credentials-file .venv/supabase-integration-accounts.json`
проверяет тот же API через Vite. Пароли не передавайте в аргументах.

Каждый запуск требует нового пути отчёта. Runner сохраняет ответы, время,
хеши и журнал после каждого вопроса. Подлинность цитат и полнота смысла
оцениваются отдельно. Результаты новой версии публикуются отдельными отчётами;
старые проценты к ней не относятся.

## Календарь и отдельное демо

`GET /api/v1/requests/{uuid}/calendar.ics` проверяет доступ к одобренному отпуску
и берёт даты из заявки. Последний день включён. Google Calendar импортирует файл
вручную; перенос/отмена не синхронизируются. Подробности — [в API](ai-jana-api.md).

Без Supabase, при работающем reader:

```powershell
python -m uvicorn examples.jana_local_demo:app --host 127.0.0.1 --port 8002
```

Это отдельное приложение с вымышленной базой и без авторизации.
Оставляйте его на `127.0.0.1`; это явное демо, не резерв рабочего API.

## Исторический FAQ-режим

`jana_local.py`, `local_embeddings.py`, `knowledge_base/faq.json`,
`scripts.prepare_jana_local`, `scripts.evaluate_jana_local` и
`scripts.check_jana_release` сохранены для воспроизведения прежнего MPNet/FAQ-поиска.
Их пороги и примеры **не управляют текущим /ai/ask**. Отчёты
[по 285 вопросам](jana-release-report.md), [acceptance](jana-acceptance-report.md)
и [независимому V2](jana-independent-agents-v2-report.md) относятся к прежним версиям.
`scripts.evaluate_jana` — отдельный старый платный эксперимент OpenAI;
обычный запуск Jana его не вызывает.
