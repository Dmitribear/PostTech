# Jana: второй независимый набор из 50 вопросов

Проверка 17 октября 2026 года. **Первый прогон без исправлений: 17/50 полных ответов (34%).** Локальные ответы и ответы через Vite → FastAPI → общую Supabase совпали во всех 50 случаях. HTTP-ошибок в этом прогоне не было.

Это оценка содержания по заранее зафиксированным требованиям. Совпадение с внутренним ID карточки не требуется, а безопасный общий отказ не считается автоматически полным ответом.

## Результаты

| --- | ---: | ---: |

| Попытка подменить правила | 0 | 1 |
| **Итого** | **17** | **50** |

**21 лишний отказ** на 30 вопросов, ответ на которые есть в полных статьях. Все 9 выданных цитат подлинны, относятся к вопросу и покрывают необходимые факты. Ни одного полного правильного ответа без ссылки среди оставшихся 21 случая рецензенты не нашли.

В 20 вопросах, проверявших отсутствующие факты, неоднозначность, действия и личные данные, поведение было безопасным: конкретные правила, сроки, суммы и персональные значения не выдумывались; выполнение действий и повышение прав не заявлялись. Однако полнота объяснения — отдельный критерий. Например, отказ назначить курс не объяснил, что для назначения нужно обратиться к HR или руководителю. Ни один из шести неоднозначных вопросов не получил конкретного уточнения.

Кроме того, **12 раз Jana сказала «В базе нет подтверждённого ответа», хотя нужные сведения есть в статьях**. Это ошибочное заявление об отсутствии сведений, даже если оно не содержит вымышленной кадровой политики.

## Что показала диагностика

Без дополнительного инференса проверены функции ограничений для 21 лишнего отказа:

- 6 вопросов остановлены до поиска: 5 из-за нескольких связанных частей/вопросительных знаков, 1 из-за слишком широкой проверки персональных данных.
- 15 отказов возникли на этапе подбора ответа. Индивидуальные значения сходства повторно не рассчитывались; конкретную причину каждого такого отказа этот прогон не устанавливает.

Текущая Jana слабо переносит успешные ответы на новые формулировки. Результаты прежних известных наборов не доказывали готовность к произвольным вопросам сотрудников. При этом выданные цитаты остаются проверяемыми: основная обнаруженная проблема — чрезмерные отказы и отсутствие содержательных уточнений.

Следующая доработка должна улучшать общую обработку связанных частей вопроса, различение намерений и поиск фактов по полной базе. После неё нужен ещё один набор, которого разработчики не видели до первого прогона. **В рамках этой проверки доработки Jana не выполнялись.**

## Как обеспечена независимость

1. Два новых агента запущены без истории родительского диалога (`fork_turns=none`). Они получили только очищенные тексты 11 статей: без FAQ, `demo_questions`, прежних тестов и ответов Jana. Это вопросы агентов, не друзей или реальных сотрудников.
2. Каждый составил 25 вопросов. Другой агент проверил все 50 ожиданий до первого инференса: вопросы и классы сохранены; в 15 случаях убраны избыточные обязательные подробности ответа.
3. Проверка против 1986 известных нормализованных строк из FAQ, прежних наборов и тестов не нашла точных дублей. Лексических совпадений с отношением сходства ≥0,9 также нет. Темы и факты из тех же 11 статей могут повторяться.
4. Вопросы, минимальные факты, правила оценки и хэши версии зафиксированы **до** первого запуска. После просмотра ответов ничего не заменялось и не доразмечалось ради результата.
5. Выполнен один локальный и один последовательный HTTP-прогон. Новые рецензенты оценили по 25 ответов, видя источники, замороженные требования и ответы без автоматических баллов. Ещё один рецензент отдельно проверил все цитаты и ответы об отсутствующих фактах.
6. Проверены хэши 66 существовавших файлов приложения, базы, FAQ, тестов и оценщиков: они не изменены. Модель и пороги 0,72/0,045 сохранены. Добавлены только новый набор, отдельный инструмент проверки и отчёты.

Изоляция авторов обеспечивалась новым контекстом и ограничением разрешённых входов, а не отдельными ОС-песочницами. Полнота оценивалась агентами по зафиксированным фактам; возможна субъективность рецензентов. Подкатегории «частичный» и «не пройдено» описательны, обе не дают полного зачёта. Первичный показатель — полное покрытие необходимых фактов.

Этот балл нельзя напрямую сравнивать со старыми проверками только карточки/режима ответа: здесь отдельно оценивается полезность отказов и уточнений. После публикации результата этот набор тоже становится известным регрессионным набором.

## Воспроизведение

При установленной локальной модели и зависимостях, из корня проекта:

```powershell
python -m scripts.evaluate_jana_facts --mode local --cases knowledge_base/demo/independent_agents_v2.json --runtime-freeze docs/reports/jana-independent-agents-v2/runtime-freeze.json --output .venv/jana-v2-repeat-local.json
python -m scripts.evaluate_jana_facts --mode http --cases knowledge_base/demo/independent_agents_v2.json --runtime-freeze docs/reports/jana-independent-agents-v2/runtime-freeze.json --credentials-file .venv/supabase-integration-accounts.json --output .venv/jana-v2-repeat-http.json
```

HTTP требует запущенные backend и frontend и локальный файл тестовых учётных данных, который не входит в Git. Инструмент запрещает перезапись выходного файла и останавливается при изменении замороженной версии. Код выхода 0 означает завершённый эксперимент; смысловая успешность считается отдельной рецензией, а не этим кодом.
