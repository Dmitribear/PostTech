# Telegram: подготовка показа и постоянная работа

Сайт и бот используют один FastAPI, одну базу сотрудников и заявок, один
прогресс обучения и одну локальную Jana. Для показа используйте **локальный
демонстрационный стенд**, а не общую облачную Supabase команды. Выбор «Демо-вход»
на странице входа — отдельная демонстрация в браузере; привязка Telegram в ней
недоступна. Нужен обычный вход в настоящий аккаунт локального стенда.

## Что должно работать постоянно

| Вариант | Что требуется | Что произойдёт при выключении |
| --- | --- | --- |
| Показ с вашего компьютера | Питание, интернет, запущенный Docker Desktop, контейнеры, открытая крышка и отсутствие сна | Бот, сервер сайта и Jana становятся недоступны |
| Постоянная работа команды | Постоянно включённый сервер с Docker, интернетом, местом для модели/БД, резервными копиями и достаточными ресурсами для Qwen | Перезапуск контейнеров помогает при падении процесса, но не заменяет доступный сервер |

Сервисы уже используют `restart: unless-stopped`: Docker перезапускает упавший
процесс, но намеренно остановленный контейнер нужно запускать явно. Эта настройка
работает при запущенном Docker и не включает выключенный компьютер. См.
[правила перезапуска Docker](https://docs.docker.com/engine/containers/start-containers-automatically/).

Telegram не требует нашего публичного webhook: worker получает сообщения
исходящими запросами long polling. Для одного токена должен работать **один**
worker. При переносе на сервер сначала выключают старый экземпляр бота, затем
запускают новый с теми же проверенными данными и настройками. Бот и сайт должны
указывать на одну установку backend/БД; иначе появятся две независимые системы.
Подробнее: [Telegram getUpdates](https://core.telegram.org/bots/api#getupdates).

Локальная модель не требует оплаты каждого запроса внешнему ИИ API, но хостинг,
электричество и оборудование остаются расходами. Бесплатный спящий web-хостинг
не является готовым сервером для Qwen3.5-9B и непрерывного Telegram worker.
Постоянный сервер здесь **не развёрнут автоматически**. Перед переносом нужны
выбранный сервер, проверка скорости Jana, перенос/резервная копия данных и
настройка доступа. Не публикуйте порт PostgreSQL, секреты или внутренний reader.

Для самого чата публичный адрес сайта не нужен: телефон связывается с Telegram,
а компьютер — с Telegram и локальным API. Для кнопки «Открыть весь портал»
внутри Telegram нужен `PORTAL_PUBLIC_URL` с доступным HTTPS-адресом **этой же
установки**. `localhost` на телефоне — телефон, а не ваш компьютер. Если HTTPS
ещё не настроен, демонстрируйте бот на телефоне и сайт на компьютере. Обычный
вход на сайт сохраняется и внутри Telegram.

## Первый запуск на ноутбуке друга из main

GitHub передаёт код, Docker запускает сервисы на ноутбуке. Это не удалённый
хостинг: ноутбук должен оставаться включённым. Ни Python, ни Node для запуска
не нужны. Ниже команды для Windows PowerShell; заранее установите Git и
запустите Docker Desktop с Linux-контейнерами и включённой виртуализацией.

Первую установку и репетицию сделайте заранее: кроме образов Docker загружается
модель примерно 6,2 ГБ. Для всей системы нужна свободная оперативная память;
скорость на CPU и достаточность памяти проверьте именно на ноутбуке друга.

```powershell
git clone --branch main --single-branch https://github.com/Dmitribear/PostTech.git
cd PostTech
docker run --rm --volume "${PWD}:/workspace" --workdir /workspace python:3.12-slim python scripts/prepare_docker.py
docker run --rm --volume "${PWD}:/workspace" --workdir /workspace python:3.12-slim python scripts/prepare_telegram.py
notepad .local/telegram.env
```

В открытом файле заполните только `TELEGRAM_BOT_TOKEN=` токеном BotFather.
Сохраните файл. Остальные секреты генерируются на новом ноутбуке автоматически;
не копируйте старый `.env`, пароли или папку `.local` целиком. Если используется
командный бот, передайте его токен доверенному участнику лично, не через GitHub.
Для независимой репетиции можно создать отдельного тестового бота.

**Если используется тот же бот, сначала остановите его на прежнем компьютере.**
В Docker Desktop остановите только контейнер `posttech-local-telegram-bot-1`.
Не запускайте два экземпляра с одним токеном. Остановка старого worker сама по
себе не переносит данные и привязки.

На новом ноутбуке:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_telegram.ps1
powershell -ExecutionPolicy Bypass -File scripts/prepare_demo.ps1 -WaitSeconds 900 -StayAwake -Minutes 20
```

Это CPU-вариант. Для настроенной NVIDIA добавьте `-Gpu` к **обеим** командам.
Количество слоёв GPU можно задать `JANA_READER_GPU_LAYERS` в `.local/docker.env`;
подходящее значение зависит от видеопамяти. Наличие Docker не ускоряет модель
само по себе. Перед выступлением дождитесь прогрева и измерьте ответ Jana.

Откройте `http://127.0.0.1:8000` на ноутбуке друга. Войдите обычным входом:
`employee@posttech.demo`, пароль — `POSTTECH_DEMO_PASSWORD` из **его нового**
`.local/docker.env`. Затем **Настройки → Telegram → Подключить Telegram**.
Скопируйте свежую команду `/start <код>` из настроек в чат бота, если переход
по ссылке не сработает. После сообщения о привязке отправьте `/menu`.

Установка создаёт отдельную локальную базу с демонстрационными данными.
Заявки, прогресс и Telegram-привязка с прежнего компьютера не переносятся через
GitHub. Общая Supabase команды не изменяется. После установки данные сохраняются
в Docker volume; не удаляйте его и не генерируйте новые пароли для существующей БД.
Для обновления кода в чистой рабочей копии выполните `git pull --ff-only origin main`
и повторите запуск, заранее, до показа. Старый стенд из `test` следует сохранять
отдельно: этот запуск предназначен для свежей базы `main`, а не автоматической
миграции прежнего volume с другой историей SQL.

На выступлении показывайте сайт на ноутбуке и чат бота на телефоне.
Публичный HTTPS для этого не нужен. Открытие самого сайта с телефона потребует
отдельной публикации этой же установки.

## За 20–30 минут до показа

1. Подключите питание и стабильный интернет. Подготовьте запасной интернет,
   если он есть. Закройте игры и другие приложения, занимающие GPU/оперативную
   память. Не обновляйте модель, зависимости и ветку непосредственно перед показом.
2. Откройте PowerShell **в корне той рабочей копии**, где находятся рабочие
   `.local/docker.env` и `.local/telegram.env`. Не копируйте файлы в презентацию
   или чат и не показывайте их на проекторе. Настройка нового бота описана в
   [основной инструкции](telegram.md).
3. Заранее запустите контейнеры. Сборка и загрузка модели могут занять время:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/start_telegram.ps1 -Gpu
   ```

   `-Gpu` используйте только с уже настроенной NVIDIA-конфигурацией. Для CPU
   уберите этот флаг; после смены режима заранее проверьте фактическую скорость.
   `start_telegram.ps1` может собрать образы, создать отсутствующие локальные
   файлы настроек и применить локальные миграции — это подготовка, а не действие
   для середины выступления.
4. Проверьте готовность и включите временное предотвращение сна:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/prepare_demo.ps1 -Gpu -WaitSeconds 600 -StayAwake -Minutes 20
   ```

   Скрипт проверяет Linux Docker, контейнеры, страницу сайта, API/БД, reader,
   heartbeat бота и доступность Telegram через `getMe`. Затем входит локальным
   сотрудником и ждёт `/api/v1/ai/status` до состояния `ready`. Пароль берётся
   из приватного файла, токен входа остаётся в памяти и не выводится. Контейнеры
   и конфигурация не меняются, заявки/курсы не создаются, Telegram-сообщения не
   отправляются, искусственный вопрос `/ask` не запускается.

   В текущем Compose `JANA_WARMUP_ENABLED=true`: API после запуска сам
   прогревает полный контекст базы знаний. `warming` означает, что прогрев ещё
   идёт, `unavailable` — временную недоступность; скрипт ждёт только указанный
   срок. `disabled` останавливает проверку: используйте текущую конфигурацию
   запуска с включённым прогревом. Максимум `-WaitSeconds` — 900; `0` означает
   одну проверку без повторных запросов. Базовый preflight ограничен отдельно
   90 секундами, вход — 15 секундами. Итог: `.local/demo-preflight.json`.

   `ready` подтверждает завершение прогрева, а не гарантирует одинаковую
   задержку всех будущих ответов или безошибочность модели. До показа вручную
   проверьте известный вопрос, открытие его источника и отказ на неизвестный факт.
5. Оставьте окно скрипта открытым. После проверки защита от автоматического сна
   действует ещё 20 минут; `Ctrl+C`, закрытие процесса или завершение срока
   снимают её. Схема питания Windows постоянно не меняется. Крышку не закрывайте,
   ручной Sleep/выключение не используйте: эта защита их не отменяет. При ошибке
   preflight защита также освобождается. Механизм описан в
   [Microsoft SetThreadExecutionState](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate).

Для проверки без удержания компьютера во включённом состоянии:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/prepare_demo.ps1 -Gpu -WaitSeconds 600
```

Сайт и бот делят одну очередь Jana: один вопрос обрабатывается, ещё два могут
ждать до 60 секунд. При переполнении или истечении ожидания нужно повторить
вопрос; это отдельно обозначенная занятость, а не ошибка входа. На показе
дождитесь ответа перед следующим вопросом. Точный повтор вопроса может
вернуться из кэша на 5 минут; перед этим проверяется актуальная опубликованная
база. Изменённые статьи исключают использование прежнего ответа. Новый вопрос
по-прежнему передаётся модели вместе со всей базой.

## Вход и точная привязка Telegram

Для локального стенда подготовлены аккаунты:

| Участник | Логин | Где удобно показывать |
| --- | --- | --- |
| Сотрудник | `employee@posttech.demo` | Сайт + личный Telegram |
| Руководитель | `manager@posttech.demo` | Отдельная вкладка/профиль браузера |
| HR | `hr@posttech.demo` | Ещё одна вкладка/профиль браузера |
| Директор, если понадобится | `director@posttech.demo` | Отдельная вкладка/профиль браузера |

Пароль этих аккаунтов — значение `POSTTECH_DEMO_PASSWORD` в приватном
`.local/docker.env`. Не пишите его в инструкцию и не демонстрируйте экран ввода
с раскрытым паролем. На сайте проверяйте имя и роль, прежде чем согласовывать.

1. Откройте локальный сайт на компьютере. Обычно это `http://127.0.0.1:8000`;
   точный адрес печатает preflight. Войдите по почте и паролю сотрудника.
2. Меню профиля справа вверху → **Настройки → Telegram**.
3. Если уже написано «Telegram подключён» и указан ваш аккаунт, ничего заново
   привязывать не нужно. Проверьте переключатель уведомлений.
4. Если связи нет, нажмите **«Подключить Telegram»**. Откройте новую личную ссылку,
   затем нажмите **Start/Старт** в чате с ботом. Ссылка одноразовая, действует
   10 минут и не должна пересылаться другим людям.
5. Если ссылка открыла только чат, скопируйте на сайте **всю запасную команду**
   из поля под пояснением «Если кнопка не сработала…»: `/start <личный код>`.
   Отправьте её целиком этому боту. `<личный код>` — обозначение: не набирайте
   эти слова и не отправляйте один `/start` без кода. При запрете буфера обмена
   выделите команду в поле и скопируйте вручную.
6. Дождитесь сообщения **«Аккаунт связан с сайтом»** и меню бота. На сайте нажмите
   **«Обновить статус»** — должно появиться **«Telegram подключён»**. В боте
   отправьте `/profile` и сравните профиль с сайтом.

На текущем компьютере переход по ссылке не всегда передавал код в Telegram;
полная команда из шага 5 успешно подключила аккаунт. Это однократная операция:
после подключения достаточно открыть `@JanaMenHr_bot` и отправить `/menu`.

Один аккаунт сотрудника связан с одним Telegram, и один Telegram — с одним
аккаунтом сотрудника. На показе не переключайте один Telegram между сотрудником,
руководителем и HR: это требует отключения и новой привязки, а старые кнопки
перестают подходить. Руководителя и HR удобнее показывать на сайте. Если друзья
хотят использовать их роли именно в боте, заранее привяжите **их отдельные
Telegram-аккаунты** к соответствующим аккаунтам сайта.

После привязки отправляются новые уведомления; старые события автоматически
не рассылаются. Не используйте `/stop` и «Отключить Telegram» до окончания
показа. Это действительно удаляет связь, а не просто закрывает меню.

## Сценарий на 10 минут

Сначала прогоните его один раз заранее и измерьте время на этом компьютере.
Уточните у команды, что показанные профили, регламенты и суммы — **демонстрационные
данные**. Выберите незавершённый курс и уже согласованный отпуск для `.ics`.
Все новые демонстрационные заявки помечайте комментарием `DEMO JURY` и датой.

| Время | Действие | Что объяснить жюри |
| --- | --- | --- |
| 0:00–1:00 | На сайте открыть профиль сотрудника; в боте `/profile` | «Сайт и Telegram показывают один аккаунт из общей базы, а не два набора данных». |
| 1:00–2:00 | `/courses` → назначенный курс → урок. Прочитать и нажать «Я изучил(а) урок»; обновить курс на сайте | «Материал и прогресс общие». Если курс уже завершён, показать существующий результат, а не обнулять его. |
| 2:00–3:00 | `/menu` → «Аванс» → `100` → комментарий `DEMO JURY <дата>` → «Подтвердить». Открыть эту заявку на сайте | «Действие сохраняется только после подтверждения, запись сразу видна в другом интерфейсе». |
| 3:00–4:30 | Руководитель на сайте согласует эту заявку; HR окончательно одобряет. На телефоне показать уведомления, в `/requests` открыть карточку и «Обновить» | «Сначала руководитель, затем HR. Состояние одинаковое на сайте и в боте». Аванс демонстрационный, реальную выплату система здесь не выполняет. |
| 4:30–5:00 | В боте `/calendar` или карточка уже согласованного **отпуска** → «Скачать .ics» | «Файл содержит доступные согласованные отпуска и импортируется в Google Calendar вручную». Аванс в календарь не попадает. |
| 5:00–7:00 | `/ask Кто окончательно одобряет отпуск?` → дождаться ответа → открыть кнопку «Источник» | «Локальная модель понимает вопрос, выбирает фрагменты опубликованной базы; сервер проверяет цитаты и версию источника». |
| 7:00–8:30 | `/ask Какой пароль у Wi-Fi в офисе JanaPost?` | «Если подтверждённого факта нет в базе, Jana сообщает об отсутствии ответа и предлагает уточнение/HR». Перед показом убедитесь, что такого факта действительно нет в текущей базе. |
| 8:30–10:00 | Показать схему общей системы и ответить на вопросы | «Один backend, одна база, роли и история действий. Google Calendar пока через файл; постоянная доступность требует работающего сервера». |

Отметка урока и подтверждение заявки **меняют локальные демо-данные**. Preflight
их сам не создаёт. Для повторного показа не нажимайте подтверждение уже выполненной
операции: открывайте свежую карточку через `/menu`, проверяйте историю и используйте
новую помеченную заявку только если она действительно нужна для демонстрации.

Jana может отвечать дольше отведённого окна. Пока она работает, не отправляйте
этому же Telegram-пользователю новый вопрос и не нажимайте подряд другие действия:
бот попросит дождаться предыдущего запроса. В это время расскажите про архитектуру
на сайте или презентации. Если укладываться в 10 минут не получается, покажите
заранее сохранённый результат **с явной пометкой «предыдущий прогон»**, а живой
ответ откройте, когда он придёт. Не выдавайте запись за ответ текущего запроса.

Импорт `.ics` в Google лучше подготовить до выступления в отдельный тестовый
календарь. На сцене достаточно показать файл и ранее проверенные даты: повторный
импорт может создать дубликаты, автоматической синхронизации пока нет.

## Если что-то пошло не так

| Симптом | Что сделать |
| --- | --- |
| Бот молчит | Проверить питание/интернет и preflight. Убедиться, что запущен один `telegram-bot`. Не запускать второй worker и не вызывать `getUpdates` вручную. |
| «Свяжите аккаунт» после `/start` | Открыть настройки сайта и отправить полную свежую команду с кодом; затем обновить статус. |
| Ссылка истекла/использована | Если сайт уже показывает подключение — `/menu`. Если связи нет — создать новую ссылку на сайте. |
| Старая кнопка не работает | `/menu` и заново открыть нужную заявку/курс. Черновики истекают через 15 минут и теряются при перезапуске worker; сохранённые данные остаются в БД. |
| `warming` / медленный первый ответ | Дождаться preflight и провести короткую репетицию. Не менять модель и не перезапускать reader перед выходом: это снова потребует прогрева. |
| `disabled` / `unavailable` | Использовать текущие Compose-файлы, проверить reader и API; не считать один зелёный контейнер доказательством готового ИИ. |
| Нет уведомления | Проверить привязку и включённые уведомления. Смотреть новую заявку и её статус на сайте; старые события после подключения не рассылаются. Не создавать дубликат заявки ради повторного уведомления. |
| Телефон не открывает сайт | Локальный URL не доступен с телефона. Использовать чат бота и сайт на компьютере либо заранее настроенный HTTPS этой же установки. |

Статус контейнеров (для GPU сохраняйте все три Compose-файла):

```powershell
docker compose --env-file .local/docker.env --env-file .local/telegram.env -f compose.demo.yaml -f compose.gpu.yaml -f compose.telegram.yaml ps
```

Для CPU уберите только `-f compose.gpu.yaml`. Во время выступления не запускайте
`down`, не удаляйте volumes и не публикуйте `docker compose config` — он раскрывает
секреты. После показа остановите временную защиту от сна через `Ctrl+C`. Если бот
должен остаться доступен, сохраняйте питание, интернет и работающие контейнеры;
закрытие вкладки браузера само по себе бота не останавливает.
